# 系统运维说明

## 1. 目录定位

`02_系统运维/` 用于承接系统从版本交付接收、客户环境部署、持续运行监控，到运维问题处置和经验沉淀的正式产物。

它按运维岗位真实工作链组织，而不是按文档类型组织。

运维工作链固定理解为：

1. 总览
2. 交付接收
3. 环境与部署
4. 运行与监控
5. 问题处置
6. 知识沉淀

---

## 4. 子目录职责

### 4.1 `00_运维总览/`

作为运维总入口，承接：

1. 系统运维总览
2. 已交付版本清单
3. 客户与环境总表
4. 总体部署架构
5. 运维待办与风险清单

说明：

1. 产品整体部署架构应放在本目录，而不是散落在具体环境或版本目录中。

### 4.2 `01_交付接收/`

按版本组织，承接：

1. 版本安装包与制品清单
2. 部署与升级手册
3. 回滚与恢复说明
4. 运维接收确认记录

固定结构建议：

```text
01_交付接收/
└── vX.Y.Z/
    ├── 00_版本交付接收总览.md
    ├── 01_版本安装包与制品清单.md
    ├── 02_部署与升级手册.md
    ├── 03_回滚与恢复说明.md
    └── 04_运维接收确认记录.md
```

### 4.3 `02_环境与部署/`

按客户和环境组织，承接：

1. 客户环境说明
2. 首次部署记录
3. 升级记录
4. 热修复部署记录
5. 环境变更记录

说明：

1. 涉及环境的变更，应放在本目录。
2. 环境对象优先于版本对象。

### 4.4 `03_运行与监控/`

按客户组织，并在客户目录下按时间持续记录，承接：

1. 系统监控配置
2. 巡检与告警记录
3. 运维操作日志
4. 运行观察与状态记录

固定结构建议：

```text
03_运行与监控/
├── 00_运行与监控总览.md
└── CUST-客户标识/
    ├── 00_客户运行总览.md
    ├── 01_系统监控配置.md
    └── 02_运行记录/
        └── YYYY-MM/
```

### 4.5 `04_运维问题处置/`

按事件组织，不按客户拆分，承接：

1. 突发运维问题
2. 系统事故
3. 性能故障
4. 运维处置记录
5. 事故复盘与整改清单

说明：

1. 这里记录的是事件本身。
2. 若事件涉及某个客户或环境，可在正文中引用对应对象，不必先按客户建目录。

### 4.6 `05_知识沉淀/`

作为运维经验库，承接：

1. 常见问题处置手册
2. 故障排查路径
3. 监控与告警经验
4. 部署与升级经验库

---

## 5. 组织规则

1. 版本接收类内容必须按版本组织。
2. 环境、部署和运行类内容必须优先按客户与环境组织。
3. 运行、监控、巡检和操作日志应按时间持续记录。
4. 运维问题处置按事件组织，不按客户切分。
5. 环境变更不进入运维问题处置，应回到 `02_环境与部署/`。

---

## 6. 一句话规则

**系统运维目录按“接收、部署、运行、处置、沉淀”的运维工作链组织，持续记录客户环境和运行事实。**

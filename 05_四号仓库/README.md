# 四号仓库

## 1. 仓库定位

`05_四号仓库/` 是项目级“测试验收、系统运维、产品运营”执行仓。

它负责承接：

1. 二号仓库 `06_产品基线/vX.Y.Z/` 的正式产品基线。
2. 三号仓库当前版本技术方案与交付约束。

它负责沉淀：

1. 版本级测试与验收执行产物。
2. 系统运维交付、部署、运行、监控和问题处置产物。
3. 产品上线、客户运营、运营支持和运营问题处置产物。

---

## 2. 不负责什么

四号仓库不负责：

1. 存放通用规范、模板和 AI 能力正文。
2. 重写二号仓库产品基线正文。
3. 重写三号仓库技术方案正文。
4. 用测试记录、运维记录或运营记录替代上游真源。

说明：

1. 通用规范、模板、AI 能力统一放在工具仓库。
2. 四号仓库只保留当前项目的正式执行产物。

## 8. 命名建议

建议优先采用以下命名方式：

1. 版本目录：`vX.Y.Z`
2. 客户目录：`CUST-客户标识`
3. 测试执行：`RUN-001_*.md`
4. 缺陷单：`BUG-001_*.md`
5. 回归记录：`REG-001_*.md`
6. 验收记录：`UAT-001_*.md`
7. 测试报告：`REP-001_*.md`
8. 部署记录：`REL-001_*.md`
9. 环境变更：`CHG-ENV-001_*.md`
10. 运维事件：`OPS-INC-001_*.md`
11. 运营事件：`OPR-INC-001_*.md`

---

## 9. 回流规则

1. 若发现产品基线口径缺失或错误，应回流二号仓库，不在四号仓库静默修改需求事实。
2. 若发现技术方案前提不成立，应回流三号仓库，不在四号仓库静默重定义技术边界。
3. 若发现客户反馈已超出当前版本范围，应回流版本治理链路，不直接在四号仓库当作当前版本问题处理。
4. 若运维或运营问题本质上属于代码缺陷，应回到 `01_测试验收/` 形成版本级 Bug 或回归记录。

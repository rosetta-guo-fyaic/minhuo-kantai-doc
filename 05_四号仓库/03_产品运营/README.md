# 产品运营说明

## 1. 目录定位

`03_产品运营/` 用于承接产品从业务理解、系统上线、客户运营，到运营问题处置和经验沉淀的正式产物。

它按运营岗位真实工作链组织，而不是按静态资料 / 动态资料简单拆分。

运营工作链固定理解为：

1. 总览
2. 产品与业务理解
3. 系统上线
4. 客户运营
5. 运营问题处置
6. 知识沉淀

---

## 4. 子目录职责

### 4.1 `00_运营总览/`

作为运营总入口，承接：

1. 产品运营总览
2. 客户运营状态总表
3. 运营重点与待办清单

### 4.2 `01_产品与业务理解/`

承接运营岗位的静态理解材料，包括：

1. 产品使用手册
2. 业务操作流程
3. 不同角色的 SOP
4. 关键业务场景说明

说明：

1. 这里是运营侧理解产品和业务的知识入口。

### 4.3 `02_系统上线/`

按客户组织，承接：

1. 环境启用说明
2. 培训与宣导计划
3. 初始化准备清单
4. 上线执行记录
5. 上线确认记录

说明：

1. 这里关注的是运营视角的“客户上线与启用”，不是技术部署动作本身。

### 4.4 `03_客户运营/`

按客户组织，并在客户目录下按时间持续记录，承接：

1. 运营操作日志
2. 数据监控与效果跟踪
3. 客户支持记录
4. 阶段运营分析

固定结构建议：

```text
03_客户运营/
├── 00_客户运营总览.md
└── CUST-客户标识/
    ├── 00_客户运营总览.md
    └── 01_运营记录/
        └── YYYY-MM/
```

说明：

1. 数据与效果跟踪应放在客户运营目录下，不单独平行拆出。
2. 运营记录应按时间持续沉淀。

### 4.5 `04_运营问题处置/`

按事件组织，不按客户拆分，承接：

1. 突发运营问题
2. 客户使用事故
3. 运营异常处置
4. 运营复盘与整改清单

说明：

1. 这里记录的是运营事件本身。
2. 若事件涉及具体客户，可在正文中引用客户对象，不必先按客户建目录。

### 4.6 `05_知识沉淀/`

作为运营经验库，承接：

1. 常见问题处理手册
2. 角色支持经验库
3. 客户上线经验库
4. 运营优化经验库

---

## 5. 组织规则

1. 产品理解类资料放 `01_产品与业务理解/`。
2. 客户启用和上线过程放 `02_系统上线/`。
3. 日常客户运营和数据跟踪放 `03_客户运营/`。
4. 运营问题和事故按事件组织，统一放 `04_运营问题处置/`。
5. 运营经验与可复用方法沉淀到 `05_知识沉淀/`。

---

## 6. 一句话规则

**产品运营目录按“理解、上线、运营、处置、沉淀”的运营工作链组织，持续记录客户使用与业务支持事实。**

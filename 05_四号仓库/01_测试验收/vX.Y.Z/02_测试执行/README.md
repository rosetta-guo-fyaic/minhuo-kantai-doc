# 测试执行目录说明

## 1. 目录定位

`02_测试执行/` 用于沉淀当前版本的正式测试执行过程与证据。

这里回答的是：

1. 测试在哪个环境执行。
2. 使用了哪些测试数据。
3. 分几轮执行。
4. 每轮执行结果如何。

---

## 2. 建议内容

建议至少包括：

1. `00_测试环境与数据准备.md`
2. `RUN-001_首轮测试执行记录.md`
3. `RUN-002_回归测试执行记录.md`
4. `evidence/`

说明：

1. 多轮执行应分别记录。
2. 截图、日志、导出文件等证据可集中存放并在记录中引用。

## 4. 编写规则

1. 测试执行应引用 `01_测试设计/` 中的正式用例。
2. 每轮执行应明确执行范围、执行人、时间、环境和结果。
3. 执行发现的问题，应同步沉淀到 `03_Bug管理/`。
4. 不应在这里直接给出版本最终放行结论，放行结论进入 `06_版本放行与交付建议/`。

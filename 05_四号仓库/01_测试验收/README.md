# 测试验收说明

## 1. 目录定位

`01_测试验收/` 用于承接版本级测试设计、测试执行、Bug 管理、产品验收、测试报告和版本放行建议。

它回答的问题是：

1. 当前版本如何测试。
2. 当前版本测试执行结果如何。
3. 当前版本有哪些缺陷。
4. 当前版本产品验收是否通过。
5. 当前版本是否具备交付与放行条件。

---

## 2. 组织方式

本目录必须按版本组织。

固定结构建议：

```text
01_测试验收/
└── vX.Y.Z/
    ├── 00_版本测试与验收总览.md
    ├── 01_测试设计/
    ├── 02_测试执行/
    ├── 03_Bug管理/
    ├── 04_产品验收/
    ├── 05_测试报告/
    └── 06_版本放行与交付建议/
```

---

## 3. 上游输入

测试验收至少应承接：

1. 二号仓库当前版本产品基线：
   - `<PROJECT_ROOT>/03_二号仓库/06_产品基线/vX.Y.Z/`
2. 三号仓库当前版本技术方案：
   - `<PROJECT_ROOT>/04_三号仓库/`

说明：

1. 测试用例必须以产品基线为准。
2. 技术验证边界必须以三号仓库技术方案为准。

## 5. 子目录职责

### 5.1 `00_版本测试与验收总览.md`

记录：

1. 当前版本测试与验收范围
2. 当前轮次状态
3. 当前阻断项
4. 当前放行建议

### 5.2 `01_测试设计/`

承接：

1. 测试范围说明
2. 测试策略
3. 测试用例总表
4. 模块测试用例
5. 页面、接口、回归和非功能测试设计

### 5.3 `02_测试执行/`

承接：

1. 测试环境与数据准备
2. 多轮测试执行记录
3. 测试证据
4. 覆盖与完成情况

### 5.4 `03_Bug管理/`

承接：

1. 版本级缺陷单
2. 回归记录
3. 遗留缺陷与风险清单

### 5.5 `04_产品验收/`

承接：

1. 验收计划
2. 验收清单
3. 验收过程记录
4. 验收结论与放行建议

### 5.6 `05_测试报告/`

承接：

1. 阶段测试报告
2. 回归测试报告
3. 验收测试报告
4. 版本交付测试报告

### 5.7 `06_版本放行与交付建议/`

承接：

1. 是否具备上线条件
2. 需阻断的问题
3. 可带病交付事项
4. 交付约束说明

---

## 6. 运行规则

1. 每个版本必须单独建目录，不得平铺记录。
2. 所有 `RUN-*`、`BUG-*`、`REG-*`、`UAT-*`、`REP-*` 都必须归属某个版本。
3. 若发现产品基线范围有误，应回流二号仓库。
4. 若发现技术方案前提不成立，应回流三号仓库。
5. 若发现问题本质上属于运维运行问题或运营支持问题，不应强行记录为版本级 Bug。

---

## 7. 一句话规则

**测试验收目录只承接“当前版本是否可验证、可验收、可放行”的正式执行产物。**

# Agent 使用说明

## 1. 目录定位

本目录用于说明 Agent / Skill 在“项目仓库模板”及其派生真实项目仓库中的调用边界。

本目录不承载公共真源正文，只承载项目仓库侧的协作说明。

## 2. 基本原则

1. 先检查当前工作区是否为标准项目仓库。
2. 先判断当前任务属于哪个仓库、哪个阶段。
3. 先引用工具真源，再生成项目级产物。
4. 不在项目仓库内部维护第二套规范、模板、方法论和 AI 工作站副本。

## 3. 开始工作前必须确认

Agent 在项目仓库中开始正式工作前，至少应先确认：

1. 当前工作区是否符合 `00_项目仓库模板/` 结构。
2. 当前任务属于 `00_OD工作区 / 01_零号仓库 / 02_一号仓库 / 03_二号仓库 / 04_三号仓库 / 05_四号仓库` 中的哪一层。
3. 当前阶段应引用的工具真源目录是什么。
4. 当前产物属于项目级产物，还是工具级公共真源。

## 4. 推荐调用顺序

推荐按以下顺序执行：

1. `warehouse-router`
2. 对应阶段 Skill
3. `doc-gatekeeper`
4. `git-sync`

其中：

1. `warehouse-router` 负责先做项目仓库结构检查、仓库归属判断和阶段路由。
2. 对应阶段 Skill 负责生成本阶段正式项目产物。
3. `doc-gatekeeper` 负责正式落库前检查目录、模板、编号和追溯关系。
4. `git-sync` 负责 Git 状态检查、提交和推送协作。

1. OD 工作区与需求确认承接，优先引用：

   - `06_工作规范/03_项目管理规范/`

   - `08_AI工作站/01_AI能力模块/02_零号仓库能力模块/`
3. 一号仓库阶段，优先引用：
   - `06_工作规范/04_需求分析规范/`

   - `08_AI工作站/01_AI能力模块/04_二号仓库能力模块/`
5. 三号仓库与四号仓库阶段，优先引用：

2. 若涉及研发方法、分析方法、设计方法，统一优先引用 `09_DIC研发方法论/`。

## 6. 输出要求

1. 输出必须落到当前阶段正确目录。
2. 输出应明确所依据的工具真源。
3. 输出不得覆盖公共真源正文。
4. 输出前应确认当前工作区结构检查已通过。

## 7. 推荐执行步骤

1. 先做项目仓库结构检查。
2. 再识别当前仓库与阶段。
3. 再读取当前仓库 `README.md`、对应规范和对应模板。
4. 然后调用对应 Skill 生成项目级结果。
5. 最后做门禁检查和 Git 收尾。

## 8. 禁止越界事项

1. 不得在项目仓库模板内沉淀工具真源副本。
2. 不得在未确认阶段时直接生成后续阶段正式结论。
3. 不得绕过 `README.md` 和阶段边界在错误目录落文档。
4. 不得在非空且结构不一致的工作区中继续正式落库。
5. 不得把项目级补充说明回写到公共规范、模板、方法论或词典真源。

## 9. 一句话说明

**Agent 在项目仓库中负责按正确目录生成项目级产物，公共真源目录负责提供统一规则与能力。**

# 产品需求说明

## 1. 目录定位

`05_产品需求/` 是二号仓库的 PRD 正式收口层，也是二号仓库的交付真源层。

它承接 `01_方案设计/` 的业务事实与 `02_产品原型/` 的页面事实，将其整理为研发、测试、实施可直接消费的正式需求口径。

本目录负责定义：

1. 产品需求总览
2. 模块级需求范围与模块级研发承接
3. 全局需求
4. 护栏设计
5. 权限矩阵
6. `FR-PD` 追溯总表
7. 全局对象与状态实现口径
8. 全局异常与结果态总表
9. 模块级和功能级 PRD
10. 面向产品经理的 PRD 汇编阅读版

它不负责：

1. 重新定义方案层边界
2. 单独决定页面结构、页面显隐和页面交互主定义
3. 替代产品基线冻结结论
4. 反向发明上游尚未确认的业务事实

一句话理解：

**PRD 层不是页面真源的重复描述层，而是业务事实与页面事实的交付收口层。**

## 3. 标准工作顺序

建议按以下顺序阅读和维护：

1. 先读取 `01_方案设计/`
2. 再读取 `02_产品原型/`
3. 先读取并确认 `01_方案设计/01_产品功能清单.md` 中的 `FR-*` 桥接口径
4. 先补 `00_产品需求总览.md`
5. 再建立 `04_FR-PD追溯总表.md`
6. 再按模块补 `MODxx-模块名/00_模块需求说明.md`
7. 再按模块补 `01_模块领域模型与流程承接.md`、`02_模块规则状态与护栏承接.md`、`03_模块页面动作与权限承接.md`
8. 再集中补 `01_全局需求.md`、`02_护栏设计.md`、`03_权限矩阵.md`、`05_全局对象与状态实现口径.md`、`06_全局异常与结果态总表.md`
9. 最后按功能补 `MODxx-模块名/FR-xxx_*.md`
10. 真源稳定后，汇编 `99_PRD汇编阅读版.md`
11. 一轮 PRD 定稿后，再进入 `06_产品基线/`

这里要特别区分三件事：

1. PRD 收口
   - 目标是把当前版本候选范围写成完整 PRD 真源
2. 产品基线冻结
   - 目标是把当前版本冻结为完整快照
   - 由 `06_产品基线/` 与 `AM-05` 负责
3. 基线后正式变更
   - 目标是在当前版本已冻结后形成 `CHG-*`
   - 不属于本目录的普通正文收口动作

## 3.1 文件级最小落库顺序

为避免“先写功能细节、后补全局约束”或“先冻结、后补 PRD”的倒挂，建议最少按以下顺序落库：

1. 先确认 `01_产品功能清单.md` 中本轮 `FR-*` 桥接编号与范围
2. 再落 `00_产品需求总览.md`
3. 再落 `04_FR-PD追溯总表.md`
4. 再按模块落 `MODxx-模块名/00_模块需求说明.md`
5. 再落 `01_全局需求.md`
6. 再落 `02_护栏设计.md`
7. 再落 `03_权限矩阵.md`
8. 再按模块落 `FR-xxx_*.md`
9. 再汇编 `99_PRD汇编阅读版.md`

补充判断：

1. 若当前只是 PRD 细节仍未收口
   - 继续留在本目录补正文
2. 若发现版本范围本身仍未稳定
   - 应先回一号仓库版本需求确认层补齐
   - 不应直接继续冻结基线

## 3.5 PRD 与版本治理的边界

本目录与版本治理的关系，建议按以下方式理解：

1. 本目录负责把“当前版本候选范围”收口成完整 PRD 真源
2. 本目录不负责裁决“当前版本是否正式冻结”
3. 当前版本是否可以进入基线分析，应以：
   - 零号仓库版本身份真源
   - 一号仓库版本需求确认真源
   - 本目录 PRD 真源收口状态
   三者共同判断
4. 若在 PRD 阶段发现：
   - 需求范围新增或删除已影响当前版本边界
   - 关键功能是否纳入当前版本仍未裁决
   - 当前变化本质上已属于下一版本
   应先回一号仓库或零号仓库处理，不应继续把它写成“当前版本 PRD 已稳定”

## 3.6 进入本目录前的最小前置

进入 `05_产品需求/` 前，至少应满足：

1. `01_方案设计/00_产品解决方案总览.md` 已形成
2. 本轮范围内 `01_方案设计/MODxx-模块名/01_用户故事方案/USS-*.md` 已形成
3. `01_方案设计/02_全局方案定义/` 已形成
4. `01_方案设计/01_产品功能清单.md` 已形成，并已稳定本轮 `FR-*` 桥接编号与范围
5. `02_产品原型/03_PD桥接总表.md` 已形成
6. 本轮范围内 `02_产品原型/MODxx-模块名/PD-*.md` 已形成
7. `02_产品原型/00_原型真源闭环检查.md` 已完成
8. 页面、对象、规则、状态和权限之间的追溯链已基本完整
9. 若存在 `99_待办区/00_待办清单.md`，其中影响正式事实裁决的事项已完成回流，剩余事项均已被判定为“不阻断正式落库”
10. 若当前版本范围、纳入清单或版本归属仍存在争议，不得直接进入产品基线

## 3.7 PRD 阶段缺口拦截

出现以下任一情况，不得继续正式落库 `FR-*`，应先返回上游补齐：

1. 缺少对应 `USS-*`，无法确认功能来源与业务目标
2. 缺少对应 `PD-*`，无法确认页面动作、字段显隐与交互结果
3. 缺少 `03_PD桥接总表.md`，无法稳定确认功能与页面的正式承接关系
4. 缺少实体模型或属性口径，无法确认实体、属性、状态与来源
5. 缺少规则编号或规则归属不清，无法稳定落库规则内容
6. `02_产品原型/00_原型真源闭环检查.md` 未完成，原型尚未形成稳定真源
7. 上下游事实冲突，无法判断应以方案层、原型层还是全局约束为准
8. 系统级护栏、系统级权限、跨模块约束尚未被正式裁决
9. `99_待办区/00_待办清单.md` 中仍存在影响页面事实、规则口径、权限口径或版本范围裁决的阻断事项

## 4. 强制规则

1. PRD 不得绕过方案层和页面设计层独立定义功能事实。
2. 模块和功能编号必须继承 `01_产品功能清单.md` 中已建立的桥接口径，并与页面设计保持可追溯。
3. `00_产品需求总览.md` 只负责索引和进度，不得承载功能正文。
4. `MODxx-模块名/00_模块需求说明.md` 只负责模块范围、依赖与消费顺序，不替代 `02_产品原型/` 下的原型模块说明。
5. `FR-*` 若无法追溯到 `USS / 方案设计 / PD / ENT / 规则编号`，不得作为正式功能 PRD 落库。
6. `FR-*` 可以承接页面与功能行为，但不得重新定义页面结构、页面显隐主口径和系统级规则。
7. `01_全局需求.md`、`02_护栏设计.md`、`03_权限矩阵.md` 属于全局真源，不得把系统级约束只散落在单个 `FR-*` 中。
8. 若页面真源与功能 PRD 不一致，应先回到 `02_产品原型/` 或 `01_方案设计/` 修订，不得由 PRD 反向发明事实。
9. `04_FR-PD追溯总表.md` 必须显式承接 `03_FR桥接总表.md` 与 `03_PD桥接总表.md`，不得脱离桥接链独立编制。
10. `06_产品基线/` 只冻结范围与输入，不得承担补写需求正文的职责。
11. 任何正式文档如存在事实归属冲突，必须先裁决真源归属，再继续写入正文。
12. `99_待办区/00_待办清单.md` 只可作为过程提醒、范围说明和实现限制说明的辅助输入，不得代替 `USS / PD / 实体模型 / 全局需求 / 护栏 / 权限矩阵` 成为正式事实来源。
13. `99_PRD汇编阅读版.md` 是阅读汇编件，不得作为局部事实裁决入口。
14. 阅读版只能在真源稳定后汇编生成，不得先生成阅读版再反推真源。
15. 若当前版本已冻结，后续正式变化不得伪装成本目录中的普通 PRD 收口，应改走产品基线正式变更链路。
16. 页面相关主定义仍以 `02_产品原型/` 为准；页面之外但交付必须明确的系统级内容，以 `05_产品需求/` 为准。

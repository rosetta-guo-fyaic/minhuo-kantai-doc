# HTML 原型说明

## 1. 目录定位

`03_HTML原型/` 是二号仓库的项目级 HTML 原型输出层，也是默认主表达层。

它的作用是：

1. 承接 `02_产品原型/` 已确认的页面设计表达
2. 输出可预览、可评审、可演示的页面结果
3. 支撑产品评审、业务沟通、研发预览和页面跳转验证

它不是前端框架目录，也不是业务事实主定义来源。

本目录的正式目标不是“生成几个页面文件”，而是输出高可用、高保真、可点击、可操作的系统级 HTML 原型。

## 2. 正式口径来源

正式口径仍以下列文档为准：

1. 方案规则：`01_方案设计/`
2. 页面设计：`02_产品原型/`
3. PRD 约束：`05_产品需求/`
4. 版本冻结：`06_产品基线/`

## 2.1 本目录固定产物

一旦进入本目录，固定正式产物至少包括：

1. `00_HTML原型闭环检查.md`
2. `index.html`
3. `css/`
4. `js/`
5. `img/`
6. `pages/`
7. 与本轮 `PD-*` 对应的页面表达文件
8. `js/prototype-manifest.js`

标准目录结构如下：

```text
03_HTML原型/
├── 00_HTML原型闭环检查.md
├── README.md
├── index.html
├── css/
├── js/
├── img/
└── pages/
    ├── MOD01-模块名/
    │   ├── xxx-list.html
    │   ├── xxx-detail.html
    │   └── xxx-form.html
    └── MOD02-模块名/
```

补充说明：

1. `index.html` 是项目级 HTML 原型导航入口，用来串联当前版本的模块和页面，不是业务正式页面母版。
2. `css/`、`js/`、`img/` 是项目级共享资源目录，必须把当前原型站点实际依赖的共享资源实体化到本目录中。
3. `pages/` 是业务页面正式承载目录，所有业务页面都必须放在 `pages/` 下。
4. `pages/` 下必须按 `MODxx-模块名/` 建立模块目录，不允许把业务页面平铺在 `03_HTML原型/` 根目录。
5. 模块目录内的页面文件，应与 `02_产品原型/` 中的 `PD-*`、模块原型总览和菜单归属保持一致。
6. `js/prototype-manifest.js` 是项目级导航与壳层真源，用于驱动正式菜单、面包屑、route-tabs 和当前页高亮。
7. 每个业务页面都应声明 `window.__DIC_PAGE_CONTEXT__`，用于表达当前页编号、归属菜单页、面包屑和 route-tabs。

说明：

1. 在 `00_项目仓库模板/` 中，本目录默认只保留 `README.md`。
2. HTML 页面表达文件与 `00_HTML原型闭环检查.md` 应在真实项目仓库中、明确进入 HTML 表达阶段后按需生成。
3. 不应在模板仓库中预置空白 HTML 页面或空白闭环检查文档，以避免把示例表达层误判为正式项目输出。

## 2.2 进入本目录前的最小前置

进入 `03_HTML原型/` 之前，至少应满足：

1. `../02_产品原型/00_原型设计总览.md` 已形成
2. `../02_产品原型/00-1_系统菜单设计.md` 已形成
3. `../02_产品原型/01_全局对象模型总览.md` 与 `../02_产品原型/01_全局对象模型/` 已形成
4. `../02_产品原型/05_全局规则状态承接总表.md` 已形成
5. 本轮范围内 `MODxx-模块名/00_模块原型总览.md` 与 `01_模块页面关系与导航设计.md` 已形成
6. 本轮范围内核心 `PD-*` 已形成
7. `../02_产品原型/00_原型真源闭环检查.md` 已完成
8. 本轮 `PD-*` 中“页面类型判定与裁决”已形成，且页面类型、菜单合法性、归属关系已明确

## 2.3 进入生成前必须先修正的真源项

在开始生成或重跑 HTML 原型之前，还必须先核对以下内容是否已经在真源文档中更新：

1. `../02_产品原型/00_原型设计总览.md` 中的页面到 HTML 文件映射是否已更新为当前目录结构。
2. `../02_产品原型/04_模块页面映射表.md` 与 `MODxx-模块名/00_模块原型总览.md` 中的页面到 HTML 文件映射是否已更新为当前模块目录结构。
3. `../02_产品原型/00-1_系统菜单设计.md` 中的菜单显示名、默认入口和非菜单页归属，是否已准备直接映射到 HTML 导航。
4. 若当前项目中仍存在历史 HTML 路径、历史菜单名或旧页面目录，不得直接在旧页面上补壳；应先修正真源，再执行整站重构重跑。

## 3. 使用规则

1. HTML 页面不得单独定义新的业务状态、字段和规则
2. 如果 HTML 页面新增了业务内容，必须先回填页面设计或方案设计
3. 若 PRD 中已有要求但静态 HTML 无法真实表现，必须显式记录“原型未承载事项”
4. 原型评审输出应明确区分“HTML 已承载内容”和“仍由 PRD 承载的内容”
5. 在无特殊要求时，二号仓库应优先生成并维护 HTML 原型，再决定是否需要补 Vue 原型。

补充要求：

1. HTML 原型统一复用 `<TOOL_REPO_ROOT>/05_DIC宏观架构/03_技术框架/前端框架/前端框架2/` 的现有母版与共享资源。
2. 不得绕开统一母版重新发明第二套壳层、按钮、分页、表格和表单体系。
3. 新增页面前，应先补页面设计文档，再进入 HTML 页面生成。
4. 静态 HTML 无法承载的事项，建议记录到 `../99_待办区/`，避免评审时口径丢失。
5. HTML 页面生成时，必须读取对应 `PD-*` 中的“页面类型判定与裁决”，不得只看页面名称就自行猜测页面骨架。
6. 读取 `前端框架2` 时，必须先读以下说明文件，再读真实母版：
   - `<TOOL_REPO_ROOT>/05_DIC宏观架构/03_技术框架/前端框架/前端框架2/README.md`
   - `<TOOL_REPO_ROOT>/05_DIC宏观架构/03_技术框架/前端框架/前端框架2/CLAUDE.md`
   - `<TOOL_REPO_ROOT>/05_DIC宏观架构/03_技术框架/前端框架/前端框架2/AI生成约束.md`
   - `<TOOL_REPO_ROOT>/05_DIC宏观架构/03_技术框架/前端框架/前端框架2/前端和原型规范设计.md`
7. HTML 表达必须与页面类型一致：
   - 列表页应优先体现查询区、结果集、批量操作和跳转入口。
   - 简单表单页应优先体现单组录入、保存提交和返回闭环。
   - 复杂表单页应优先体现分组、多步骤、子表或复杂联动结构。
   - 详情页应优先体现只读展示、状态承接和后续动作。
   - 报表页应优先体现指标、图表、统计口径、下钻和导出。
   - 驾驶舱页应优先体现入口、待办、快捷操作和关键指标总览。
8. 必须在项目目录下生成站点级 `index.html`，用于串联模块目录和页面入口；它不是框架母版，但必须作为项目 HTML 原型的正式入口文件存在。
9. 必须在项目目录下生成 `css/`、`js/`、`img/` 共享资源目录，并确保页面引用的共享资源真实存在。
10. 业务页面必须放在 `pages/MODxx-模块名/` 下；不得把业务页面直接平铺在 `03_HTML原型/` 根目录。
11. `pages/tmp-form-modal-preview.html` 只是框架侧临时预览页，不纳入项目正式页面类型映射，也不应直接迁入项目输出目录作为业务页面。
12. 模块目录内页面之间、菜单入口、卡片入口、返回路径、`route-tabs` 路径，都必须指向项目内真实存在的页面文件，且路径应以 `pages/` 为根进行组织。
13. 不得把导航页中的 Tailwind / Lucide 技术栈直接搬进业务页，除非后续规范明确允许。
14. 若 HTML 表达层发现 `PD-*` 中的页面类型结论与页面结构明显不一致，应先回填 `02_产品原型/` 做裁决，不得在 HTML 层私自改型。
15. 正式项目页面不得保留 `页面模板demo`、`列表页模板`、`Mock Admin` 等 demo 文案。
16. 正式项目页面不得保留 `href="#"`、`javascript:void(0)` 或未声明目标页的假链接。
17. 页面中的弹窗标题、详情标题、字段名、按钮文案必须与当前 `PD-*` 真源一致，不得遗留其他页面内容。
18. 菜单、面包屑、`route-tabs` 和项目级 `index.html` 中展示的菜单显示名，必须与 `00-1_系统菜单设计.md` 逐字一致。
19. 若只是替换了导航壳层，但页面正文仍保留旧页面内容、旧弹窗标题或跨页面字段，应视为未完成重构。
20. 不得跳过项目级原型骨架，只生成零散页面后宣称 HTML 原型已完成。
21. 正式 HTML 原型至少应满足：站点可打开、菜单可进入、页面可访问、主流程可点击、主要操作可承载、返回路径可回退。

## 4. 建议生成顺序

1. 先读取 `../02_产品原型/` 下的正式真源
2. 逐页读取本轮 `PD-*` 中的页面类型判定与裁决、动作闭环和显隐分析
3. 再按顺序读取 `前端框架2` 的说明文件、对应 `pages/*.html` 正式母版、`css/shared.css`、`js/shared.js` 和页面专属 `js/*.js`
4. 先建立项目级输出骨架：`index.html`、`css/`、`js/`、`img/`、`pages/`
5. 再生成 `js/prototype-manifest.js`，声明菜单树、页面路径、模块与壳层文案
6. 再把本轮实际依赖的共享资源复制或实体化到项目目录的 `css/`、`js/`、`img/`
7. 再按 `MODxx-模块名/` 建立 `pages/` 下的模块目录
8. 再生成本轮 `PD-*` 对应的 HTML 表达文件，并写入对应模块目录，同时为每个页面声明 `window.__DIC_PAGE_CONTEXT__`
9. 再生成项目级 `index.html`，用于导航到各模块和页面
10. 再检查页面骨架是否与页面类型一致，以及菜单入口、主按钮、返回路径、资源引用、菜单显示名逐字一致、demo 残留和死按钮
11. 最后回写 `00_HTML原型闭环检查.md`

一句话要求：

1. 严格按既定步骤生成，不跳步。
2. 严格按真源承接，不走样。
3. 严格以高可用、高保真、可点击、可操作为交付标准，不以静态页面数量作为完成标准。

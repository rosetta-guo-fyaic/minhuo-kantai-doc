# 待办区说明

## 1. 目录定位

`99_待办区/` 用于承接二号仓库中的过程性待办，不属于正式真源层。

它主要用于记录：

1. HTML 原型未承载事项
2. Vue 原型未承载事项
3. 评审遗留问题
4. 待确认设计点
5. 需要在三号仓库继续验证的实现疑点

## 1.1 固定过程记录文档

本目录建议统一使用：

1. `00_待办清单.md`

说明：

1. 在 `00_项目仓库模板/` 中，本目录默认只保留 `README.md`。
2. `00_待办清单.md` 应在真实项目仓库中、确有过程性待办需要登记时按需生成。
3. 不应在模板仓库中预置空白待办清单，以避免把空白过程记录误判为已登记待办。

该文件用于集中登记：

1. HTML 原型未承载事项
2. Vue 原型未承载事项
3. 页面真源未完全裁决但暂不阻塞继续推进的事项
4. 评审遗留问题
5. 需要在后续 PRD、基线或三号仓库继续承接的问题

## 1.2 待办事项分类规则

`99_待办区/` 中的事项，建议至少区分为以下两类：

1. 可记录但不阻断继续推进的事项
2. 必须回流正式真源后才能继续推进的事项

### 1.2.1 可记录但不阻断的事项

以下事项可以登记到 `00_待办清单.md`，并允许在满足门禁条件后继续推进：

1. HTML / Vue 表达层当前无法真实承载，但页面真源和业务事实已稳定的演示限制
2. 评审后形成的视觉优化建议、前端实现建议、演示增强建议
3. 不影响当前页面结构、动作闭环、显隐口径和规则裁决的体验增强项
4. 需要在三号仓库或研发实现阶段继续验证的技术实现疑点
5. 已明确纳入后续版本，但不纳入本轮冻结范围的增强项

### 1.2.2 必须回流真源的事项

以下事项不得只停留在待办区，必须先回写对应正式真源，再决定是否继续推进：

1. 方案边界、业务规则、实体定义、状态口径、权限口径仍未裁决
2. 页面结构、页面动作、页面显隐、菜单合法性、入口来源、返回路径仍未稳定
3. `USS / PD / FR / 实体模型 / 护栏 / 权限矩阵` 之间出现事实冲突
4. 原型未承载的内容已经影响 PRD 正式描述、验收标准或版本冻结结论
5. 待办事项本质上仍是“需求未确认”或“真源未形成”，而不是表达层承载限制

## 2. 使用边界

本目录可以记录问题，但不能替代以下正式真源：

1. 方案问题回到 `01_方案设计/`
2. 页面问题回到 `02_产品原型/`
3. PRD 约束问题回到 `05_产品需求/`
4. 冻结口径问题回到 `06_产品基线/`

## 2.1 与原型阶段的承接规则

1. HTML / Vue 表达层无法真实承载、但 `PD-*` 页面真源已稳定的事项，可以登记到待办区。
2. 若事项已经影响页面骨架、字段、动作、显隐、菜单挂载或返回闭环，不得只记待办，必须先回到 `02_产品原型/` 修订。
3. 原型阶段进入 PRD 前，应确认待办区中不存在仍影响页面事实裁决的未解决事项。

## 2.2 与 PRD 阶段的承接规则

1. PRD 可以读取 `00_待办清单.md` 作为“过程提醒”或“实现限制说明”的输入之一，但不得把待办清单当成事实真源。
2. 若待办事项影响 `FR-*`、`01_全局需求.md`、`02_护栏设计.md`、`03_权限矩阵.md` 的正式裁决，必须先回流 `01_方案设计/` 或 `02_产品原型/`，再进入 PRD 正式落库。
3. 只有当待办事项已经被判定为“不阻断、且不改变正式事实口径”时，PRD 才可以继续推进。
4. PRD 阶段若承接待办事项，通常只能以“实现说明、范围排除、后续版本建议、表达层限制说明”的形式出现，不得用待办代替正式需求正文。

## 2.3 建议登记字段

若创建 `00_待办清单.md`，建议至少登记以下字段：

1. 待办编号
2. 待办标题
3. 来源阶段：`HTML / Vue / 原型评审 / PRD评审 / 基线评审`
4. 事项类型：`表达层未承载 / 评审遗留 / 后续版本建议 / 技术验证 / 必须回流真源`
5. 是否阻断：`是 / 否`
6. 应回流目录：`01_方案设计 / 02_产品原型 / 05_产品需求 / 06_产品基线 / 三号仓库`
7. 当前处理结论
8. 责任人
9. 目标版本或目标阶段

## 3. 一句话说明

**待办区只记录过程问题，不直接改写正式真源；凡影响正式事实裁决的事项，必须先回流真源后再继续下游阶段。**

# Vue 原型说明

## 1. 目录定位

`04_Vue原型/` 是二号仓库的项目级 Vue 原型输出层，也是可选增强表达层。

它的作用是：

1. 承接 `02_产品原型/` 已确认的页面设计表达
2. 输出可运行、可交互、可做路由闭环验证的页面结果
3. 支撑产品评审、业务演示、研发预演和复杂交互验证

它不是前端框架母版目录，也不是业务事实主定义来源。

## 2. 正式口径来源

正式口径仍以下列文档为准：

1. 方案规则：`01_方案设计/`
2. 页面设计：`02_产品原型/`
3. PRD 约束：`05_产品需求/`
4. 版本冻结：`06_产品基线/`

## 2.1 本目录固定产物

一旦进入本目录，固定正式产物至少包括：

1. `00_Vue原型闭环检查.md`
2. 与本轮 `PD-*` 对应的页面表达文件
3. 必要的路由、壳层、公共组件或状态管理配置文件

说明：

1. 在 `00_项目仓库模板/` 中，本目录默认只保留 `README.md`。
2. Vue 页面表达文件与 `00_Vue原型闭环检查.md` 应在真实项目仓库中、明确进入 Vue 表达阶段后按需生成。
3. 不应在模板仓库中预置空白 Vue 页面、空白路由壳层或空白闭环检查文档，以避免把示例表达层误判为正式项目输出。

## 2.2 本目录的启用条件

`04_Vue原型/` 不是默认主表达层，建议仅在以下情形启用：

1. 需要 URL 化预演
2. 需要复杂交互验证
3. 需要前端联调预演
4. 需要按统一前端框架做原型迁移或重跑
5. 本轮 `PD-*` 中“页面类型判定与裁决”已形成，且页面结构已经稳定

## 3. 使用规则

1. Vue 页面不得单独定义新的业务状态、字段和规则
2. 如果 Vue 原型新增了业务内容，必须先回填页面设计或方案设计
3. 若 PRD 中已有要求但当前 Vue 原型无法真实承载，必须显式记录“原型未承载事项”
4. 原型评审输出应明确区分“Vue 已承载内容”和“仍由 PRD 承载的内容”
5. Vue 原型通常在 HTML 原型页面闭环稳定后再补，不应默认替代 HTML 原型作为主表达层。

补充要求：

1. Vue 原型统一复用 `<TOOL_REPO_ROOT>/05_DIC宏观架构/03_技术框架/前端框架/前端框架0/` 的现有模板、壳层和共享资源。
2. 不得绕开统一模板重新发明第二套壳层、路由结构、表格和表单体系。
3. 新增页面前，应先补页面设计文档，再进入 Vue 页面生成。
4. Vue 原型无法承载的事项，建议记录到 `../99_待办区/`，避免评审时口径丢失。
5. Vue 页面生成时，必须读取对应 `PD-*` 中的“页面类型判定与裁决”，不得只依据页面标题或旧页面文件直接复写。
6. Vue 表达必须与页面类型一致：
   - 列表页优先承接查询区、结果集、批量操作和页面跳转。
   - 简单表单页优先承接单组录入、保存提交和取消返回。
   - 复杂表单页优先承接多分组、多步骤、子表、审批流和复杂联动。
   - 详情页优先承接只读信息、状态展示和后续动作。
   - 报表页优先承接统计卡片、图表、下钻和导出。
   - 驾驶舱页优先承接默认入口、待办、快捷入口和关键指标总览。
7. 若 Vue 表达层发现 `PD-*` 的页面类型结论与现有页面结构冲突，应先回填 `02_产品原型/` 做裁决，不得在 Vue 层静默改型。

## 4. 建议生成顺序

1. 先确认 `../03_HTML原型/` 已形成稳定页面闭环，或已明确说明跳过 HTML 的原因
2. 再读取 `../02_产品原型/` 下的正式真源
3. 逐页读取本轮 `PD-*` 中的页面类型判定与裁决、动作闭环和显隐分析
4. 再生成本轮 `PD-*` 对应的 Vue 表达文件
5. 再检查页面骨架是否与页面类型一致，以及真实路由、按钮闭环、死按钮和低级实现错误
6. 最后回写 `00_Vue原型闭环检查.md`

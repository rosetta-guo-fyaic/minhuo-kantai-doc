# 二号仓库

## 1. 仓库定位

`03_二号仓库/` 是项目产品设计主仓。

它负责把一号仓库已稳定的需求输入，继续收口为：

1. 方案设计真源
2. 页面设计真源
3. HTML / Vue 原型表达
4. 交付需求真源
5. 产品基线

一句话理解：

**二号仓库负责把产品怎么做设计清楚，并沉淀为研发、测试、实施可消费的正式输入。**

补充理解：

1. 新版本承接时，二号仓库负责把上一版本基线和当前过程真源收口为新的完整产品基线。
2. 当前版本已冻结后若再发生正式变化，二号仓库负责基于人工确认的变更真源形成 `CHG-*`、快照更新判断和必要的 `hotfix` 承接结论。

## 3. 真源层级与裁决顺序

二号仓库内的事实裁决顺序固定如下：

1. 上游需求分析真源：`<PROJECT_ROOT>/02_一号仓库/03_需求分析/`
2. 方案设计真源：`<PROJECT_ROOT>/03_二号仓库/01_方案设计/`
3. 页面设计真源：`<PROJECT_ROOT>/03_二号仓库/02_产品原型/`
4. 交付需求真源：`<PROJECT_ROOT>/03_二号仓库/05_产品需求/`
5. 产品基线：`<PROJECT_ROOT>/03_二号仓库/06_产品基线/`
6. HTML / Vue：表达层，不参与反向裁决业务事实

如果同一事实在多层出现冲突，按以下原则处理：

1. 业务边界、业务状态、跨页面规则、跨实体关系，以 `01_方案设计/` 为准。
2. 页面结构、字段、动作、去向、显隐和返回闭环，以 `02_产品原型/` 为准。
3. 系统级护栏、系统级权限、非功能需求、集成约束、研发测试消费口径，以 `05_产品需求/` 为准。
4. 当前版本最终纳入范围和冻结结果，以 `06_产品基线/` 为准。
5. HTML / Vue 原型只负责表达，不得反向定义新的业务事实。

补充说明：

1. 并非所有系统设计内容都会由页面真源承载。
2. 页面之外但交付必须明确的内容，如系统级护栏、系统级权限、非功能需求、集成约束、验收口径，应由 `05_产品需求/` 正式收口。
3. `05_产品需求/` 在生成时，必须同时学习 `01_方案设计/` 的业务事实和 `02_产品原型/` 的页面事实。

## 4. 阶段链路

二号仓库的标准推进链路为：

```text
一号仓库正式需求分析真源
-> 方案设计
-> 页面设计
-> HTML 原型
-> Vue 原型（按需）
-> PRD
-> 产品基线
```

对应目录顺序为：

1. `01_方案设计/`
2. `02_产品原型/`
3. `03_HTML原型/`
4. `04_Vue原型/`（按需）
5. `05_产品需求/`
6. `06_产品基线/`

版本场景补充：

1. 若是上一版本完成后开始做下一版本
   - 这是“新版本承接”
   - 最终应在 `06_产品基线/vX.Y.Z/` 形成新的完整快照
2. 若是当前版本已经冻结后又发生正式变化
   - 这是“基线后正式变更”
   - 应先有人工确认的一号仓库版本变更真源，再由 `06_产品基线/vX.Y.Z/03_需求范围/需求变更/` 留痕
3. 若变化属于已冻结或已发布版本的修复型调整
   - 应进一步判断是否在 `hotfix/vX.Y.Z` 分支上承接

## 6. 最小进入门禁

进入各阶段前，建议最少满足：

1. 进入 `01_方案设计/` 前：一号仓库正式需求分析输入已形成
2. 进入 `02_产品原型/` 前：方案阶段正式产物已形成，核心故事与功能范围已稳定
3. 进入 `03_HTML原型/` 前：页面真源与原型闭环检查已形成
4. 进入 `04_Vue原型/` 前：HTML 页面闭环已稳定，或已明确跳过 HTML 的原因
5. 进入 `05_产品需求/` 前：`PD-*` 页面真源已形成，追溯链基本完整
6. 进入 `06_产品基线/` 前：PRD 正式产物已形成，范围和口径已稳定
   - 若是新版本冻结，零号仓库版本身份和一号仓库 `00_版本需求清单.md` 已齐备
   - 若是基线后正式变更，已存在人工确认的 `01_版本需求变更确认.md`

## 8. 强制边界

1. 不承载项目启动准入信息
2. 不承载研发实现、测试执行、发布运维正文
3. 不在本仓库内复制公共规范、模板和 AI 工作站正文
4. 不允许跳过上游真源直接生成下游正式文档
5. 不允许用 HTML / Vue 原型反向裁决方案、页面、权限或基线口径
6. 不允许用待办区替代正式真源层
7. 不允许把新版本正常承接误写成上一版本 `CHG-*`
8. 不允许在缺少人工确认的 `01_版本需求变更确认.md` 时，直接落库基线后正式变更
9. 不允许把页面之外但交付必须明确的系统级内容，强行压进 `02_产品原型/`
10. 不允许让 `05_产品需求/` 单独脱离 `01_方案设计/` 与 `02_产品原型/` 自行定义业务或页面事实

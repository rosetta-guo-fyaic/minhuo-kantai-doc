# 技术方案评审与放行说明

## 1. 目录定位

`00_技术方案评审与放行/` 用于承接当前版本、当前研发范围在进入实施编排前的技术方案门禁事实。

这里不是技术方案正文区，而是三号仓的门禁控制面。

当前目录主要承接：

1. 当前版本需求范围与技术承接清单
2. 版本级技术方案门禁结论
3. 评审会结论与人工放行事实
4. 模块技术包进入实施编排前必须具备的评审留痕
5. 面向 `AI Code / Superpowers` 的版本范围冻结入口

## 2. 主要承载内容

建议优先形成以下内容：

1. 当前版本需求范围与技术承接清单
2. 技术方案门禁记录
3. 技术方案评审单
4. 与当前范围对应的放行、阻断或人工风险接受事实

建议优先形成的文件包括：

1. `01_当前版本需求范围与技术承接清单.md`
2. `02_技术方案门禁记录.md`
3. `03_技术方案评审单.md`

若同一版本存在多轮评审或多批次门禁，可继续按编号追加。

## 3. 使用规则

1. 当前版本进入技术方案展开前，应先在本目录形成正式“需求范围与技术承接清单”。
2. 当前范围进入实施编排前，应先在本目录形成正式门禁事实。
3. 这里只承接范围冻结、门禁记录和评审事实，不替代 `01_总体技术方案/`、`02_模块技术方案/` 和 `03_跨模块专项/` 的正文内容。
4. 当前范围若命中技术评审条件但本目录无正式事实，不得继续进入研发实施。
5. 若当前范围后续要交给 `AI Code / Superpowers`，本目录中的版本范围、门禁结论和评审事实应保持稳定编号和唯一真源路径，作为后续 `AI_CODE_INPUT/` 的总入口。

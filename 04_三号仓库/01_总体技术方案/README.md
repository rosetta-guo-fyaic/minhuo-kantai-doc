# 总体技术方案说明

## 1. 目录定位

`01_总体技术方案/` 是三号仓库的总控设计区。

这里用于承接项目级技术蓝图、系统分层、服务划分、模块边界和整体落地策略，负责把二号仓库产品基线转化为研发可执行的总体技术输入。

这里回答的是“整个版本或整个系统怎么落地”，不是“某个模块的具体前后端怎么实现”。

进入本目录前，建议先在 `00_技术方案评审与放行/` 形成 `01_当前版本需求范围与技术承接清单.md`，锁定当前版本纳入范围与技术承接去向。

## 2. 主要承载内容

建议优先形成以下内容：

1. 系统整体实现思路
2. 模块与服务划分方案
3. 关键约束、依赖关系和技术选型
4. 与当前版本需求范围、产品基线、实体模型、接口边界的对应说明
5. 跨模块统一约束与共性规则

建议优先形成的全局文件包括：

1. `01_总体技术方案.md`
2. `02_系统依赖清单.md`
3. `03_研发实现约束清单.md`
4. `04_技术方案到产品基线映射.md`

按需补充：

1. `05_降级策略清单.md`
2. 其他仅面向全局层成立的支撑文件

## 3. 使用规则

1. 这里解决的是“整体怎么落地”，不是详细编码实现。
2. 跨前后端、跨服务、跨数据域的公共约束，应优先收口在本目录。
3. 某个模块的前端、后端、数据、风险、实施和交接正文，应进入 `02_模块技术方案/`。
4. 若事项同时影响多个模块但又不适合作为全局总则，可进入 `03_跨模块专项/`。
5. 若当前版本需求范围与技术承接去向未冻结，不宜直接展开总体技术方案。
6. 若总体技术方案未明确，不宜直接展开大规模模块级细节设计。

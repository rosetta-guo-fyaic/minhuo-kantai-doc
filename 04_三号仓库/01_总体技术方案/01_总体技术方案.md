## 2. 技术方案目标

1. 核心问题：把冻结基线（FR-001~009 / PD-001~005）落地为一个本地单机可运行的「敏感货可接性看台」——看现状（就严三态）、分地区（矩阵+下钻）、看变化（append-only 时间线）、简版维护（登记/修订必留痕）、品名中英查询。
2. 覆盖范围：三表规则库 + 8 个 REST API + 5 个静态页面 + 种子数据；就严合并口径全系统单点实现。
3. 边界（与基线排除范围一致，本方案不做）：REQ-006~010、第四展示态、判定推理、审核流、权限分级、登录体系、外部系统集成、导出、自动采集、群播报。

## 4. 技术选型定版

| 层 | 选型 | 版本/口径 | 定版理由 |
|----|------|-----------|----------|
| 语言 | Python | 3.14（本机实测 3.14.3；下限 3.12） | 单机脚本化交付，标准库 sqlite3 覆盖数据层 |
| Web 框架 | FastAPI + uvicorn | fastapi ≥0.115，uvicorn ≥0.30 | 声明式路由 + Pydantic 入参校验（安全约束落地成本最低），单进程即可 |

| 部署 | 本地单机 | `uvicorn app.main:app --port 8000`，浏览器访问 `http://localhost:8000` | URD 本地单用户场景；无容器、无反向代理 |

## 7. 非功能约束（模板 02/03 相关项承接）

### 7.1 性能（URD §5.1，单机演示量级）

1. 页面首屏加载 ≤3s、接口响应 ≤500ms（本地、种子数据量级）。实现口径：无网络跳数、无外部资源、单文件 SQLite、查询走 §M01 索引；不引入缓存层（数据量级不需要，且即时生效优先）。
2. 列表不分页（FR-002 明示样例量级单页可容纳，>500 条由四号仓库回归验证）。

### 7.2 安全（基线 FR 索引 §3）

1. **SQL 注入防护**：全部 SQL 使用参数占位符（`?`），禁止任何字符串拼接进 SQL；`GET /api/search` 的 LIKE 通配符（`%` `_` `\`）做 ESCAPE 转义。落点：db.py 统一出口，Task-004/005 验收项。
2. **输入校验**：API 入参全部经 Pydantic 模型（类型/长度/枚举白名单/必填），枚举值域 = OD 字典 §2；长度上限对齐 ENT 字段定义（64/128/500/200/32）。前端 XSS 防护：所有用户数据入 DOM 前经统一 `escapeHtml`。
3. **权限**：v1.0.0 无登录、无权限分级（QL-002 冻结结论，非技术缺口，不自行加）。
4. **数据不可抵赖**：change_log 只增不改——API 面无编辑/删除端点（逐端点证明见 `03_跨模块专项/01-数据一致性与事务.md`）+ SQLite 触发器库级防线（M01 §5.4）双层。

### 7.3 可移植与运维

1. 交付即运行：克隆两仓 → `pip install fastapi uvicorn` → 初始化库 → 启动，无其他环境依赖。
2. v1.0.0 无迁移体系：表结构变更 = 重建库（DDL 与种子脚本分离，见 M01 §7）；真实迁移需求留待后续版本评估（降级策略清单不适用，本项目无外部依赖可降级）。

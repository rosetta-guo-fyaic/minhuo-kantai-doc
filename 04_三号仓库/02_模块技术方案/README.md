# 模块技术方案说明

## 1. 目录定位

`02_模块技术方案/` 是三号仓库的主施工区。

这里用于按真实业务模块收口完整技术闭环，让一个模块的前端、后端、数据库、风险、实施编排和研发交接都放在同一个模块目录下，减少横向散落。
这里的“数据库”专指模块内落库真源，不默认承接外部系统接口与跨系统集成专题。

## 2. 目录组织方式

每个真实模块应单独建立一个目录，目录命名建议为：

- `MOD01_模块名/`
- `MOD02_模块名/`

每个模块目录建议优先按以下标准结构组织；其中 `09~11` 可按当前阶段形成：

```text
MODxx_模块名/
├── 01_模块技术总览.md
├── 02_前端技术方案.md
├── 03_后端技术方案.md
├── 04_数据库设计方案.md
├── 05_技术风险与验证.md
├── 06_实施编排总控.md
├── 07_研发验证与交接.md
├── 08_页面级实施清单/
├── 09_研发验证与测试流水线输入.md
├── 10_公共能力复用评估.md
└── 11_编码实现与单元测试输入.md
```

阶段化说明：

1. 若当前模块验证较轻，`09_研发验证与测试流水线输入.md` 可并入 `07_研发验证与交接.md`
2. 若当前模块不涉及公共能力判断，`10_公共能力复用评估.md` 可不单独建立
3. 若当前模块尚未进入编码阶段，`11_编码实现与单元测试输入.md` 可暂不形成

## 3. 主要承载内容

建议优先承接以下内容：

1. 模块目标、边界与主承接范围
2. 模块前端实现策略
3. 模块后端服务、内部接口与动作查询实现策略
4. 模块数据库落库与 SQL 生成输入
5. 模块风险、验证与兜底结论
6. 模块实施编排总控
7. 模块研发交接说明
8. 命中页面任务时的页面级实施清单，以及页面初始化、查询、动作、提交对应的接口调用逻辑
9. 面向 AI Code 与研发编码的代码承载矩阵、单元测试设计矩阵和编码顺序建议
10. 面向 `AI Code / Superpowers` 的模块级只读输入基础

## 4. 使用规则

1. 只要技术事实主要服务于单个模块，就优先落在对应模块目录下。
2. `04_数据库设计方案.md` 只承接模块内数据库设计，不承接外部提供接口、外部引用接口、跨系统消息或对账补偿策略。
3. 内部接口默认由 `03_后端技术方案.md` 承接，外部接口与集成专题默认转入 `03_跨模块专项/`。
4. 页面级实施清单不在三号仓根层单独散放，应挂在对应模块目录下的 `08_页面级实施清单/`。
5. 若一个事项同时影响多个模块，且无法自然归属于某个模块，应转入 `03_跨模块专项/`。
6. 全局门禁、总体方案和统一约束，不在本目录重复抄写，应分别回指 `00_技术方案评审与放行/` 与 `01_总体技术方案/`。
7. 若项目后续使用 `AI Code / Superpowers`，应以模块目录下的 `11_编码实现与单元测试输入.md` 作为模块编码入口主索引，并结合 `03_后端技术方案.md`、`04_数据库设计方案.md`、`08_页面级实施清单/` 汇编模块级输入，不要让执行阶段自行横向拼装事实。

## 2. 单点函数设计（R2 硬要求①·就严单点+可配置）

### 2.1 唯一合并入口

```python
# backend/app/merge.py —— 全项目唯一的状态合并实现（FR003-R5）
STATUS_SEVERITY = {"ACCEPTABLE": 1, "CONDITIONAL": 2, "FORBIDDEN": 3}   # FR003-R1 就严序

def merge_status(sources: list[SourceRule]) -> MergedEntry:
    """输入某展示条目（品类×大区）的全部源规则，输出合并结果。
    返回 MergedEntry(merged_status, conflict, worst_basis, worst_source, updated)。
    本函数是唯一的合并实现；任何路由/页面/脚本不得另行实现状态比较。"""
    strategy = get_strategy()            # §3 可配置点
    return strategy(sources)
```

### 2.2 strict 策略（v1.0.0 唯一启用值）

| 规则 | 实现 | FR 锚点 |
|------|------|---------|
| 合并态 = 就严序最高者 | `max(sources, key=severity)` | FR003-R2 |
| conflict = 状态去重后 ≥2 种 | `len({s.rule_status}) >= 2` | FR003-R3 |
| worst_basis = 最严源依据；并列（同状态多源）取 `updated_at` 最新、再取 id 最小（确定性） | 排序键 `(-severity, updated_at, -id)` 首位 | FR-003 §4 worst_basis |
| updated = 源规则 updated_at 最大值 | max 聚合 | FR-002 §3.1 |
| 空输入 | 不产出条目 + WARNING 日志（EX-FR003-01 数据异常分支） | FR-003 §6 |

### 2.3 消费面（谁必须调用它）

`build_display_entries(filters)` 同模块内函数：按 filters（region/source_type/status/q）拉取源规则 → 按（品类×大区）分组 → 逐组调用 `merge_status` → 应用 status 后筛（先算后筛，TD-02）。**六个只读端点（overview/rules/matrix/region-rules/changes 关联态/search）全部且仅通过本模块取数**；路由层只做 HTTP 编解码。

### 2.4 单源口径（FR003-R4，同模块实现）

`source_type` 筛选生效时：先过滤 sources 为该信源 → 无剩源的条目整组丢弃 → 剩余条目 `merged_status = 该信源状态`、`conflict 强制 False`（不标注）。实现位于 `build_display_entries` 内，**不新增第二个合并函数**——口径切换是同一函数族的参数分支。

## 3. 可配置点 STATUS_MERGE_STRATEGY（R2 硬要求①之「策略做成可配置点」分项）

```python
# backend/app/merge.py
STATUS_MERGE_STRATEGY = "strict"        # v1.0.0 定版默认且唯一合法值；来源可为环境变量 MH_MERGE_STRATEGY
_STRATEGIES = {"strict": _merge_strict} # 策略注册表：新增策略=新增键，不改调用方

def get_strategy():
    s = STATUS_MERGE_STRATEGY
    if s not in _STRATEGIES:
        raise RuntimeError(f"unknown merge strategy: {s}")   # 启动/首调即失败，静默回退禁止
    return _STRATEGIES[s]
```

## 2. 数据范围说明

1. 核心数据对象：品类（category）、源规则（rule）、变化记录（change_log）——与 ENT-001/002/003 一一对应。
2. 主数据来源：FR-007 登记写入（含新品类自动建档）+ M05 种子脚本初始化。
3. 不纳入的数据域：用户/账号/权限（QL-002 排除）、目的港结构化清单（OD-03 锁大区）、采集原始报文（REQ-006 排除）。
4. 仅展示不落库：merged_status / conflict / basis_digest / 「合并（N 源）」等——全部为 M03 计算值，任何视图表/冗余列都不建（保证就严单点与即时生效）。

## 3. 业务实体到技术表映射

| 业务实体 | 技术表 | 表类型 | 主键策略 | 生命周期 | 备注 |
|----------|--------|--------|----------|----------|------|
| ENT-001 品类 | `category` | 主表 | `id INTEGER PRIMARY KEY AUTOINCREMENT` | 只增不删（无删除 API） | 中文名唯一；英文名唯一（忽略大小写） |
| ENT-002 规则 | `rule` | 主表 | 同上 | 登记新增、修订更新（仅经 PUT 事务路径） | `(category_id, region, source_type)` 唯一 |
| ENT-003 变化记录 | `change_log` | 日志表（append-only） | 同上 | 只增；UPDATE/DELETE 被触发器禁止 | FR-008-P4 审计底线 |

逻辑关系：category 1—N rule（category_id 外键）；rule 1—N change_log（rule_id 外键）。均落库，无多对多。

## 4. 物理表结构（SQLite 方言 DDL 定版）

### 4.1 建表脚本（`database/schema.sql`）

```sql
PRAGMA foreign_keys = ON;

-- ENT-001 品类
CREATE TABLE IF NOT EXISTS category (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name_zh    TEXT    NOT NULL,                        -- 中文品类名，唯一（精确判重）
    name_en    TEXT    NOT NULL COLLATE NOCASE,         -- 英文品类名，唯一（忽略大小写，FR007-V3）
    created_at TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%S','now','localtime')),
    CONSTRAINT uq_category_name_zh UNIQUE (name_zh),
    CONSTRAINT uq_category_name_en UNIQUE (name_en),
    CONSTRAINT ck_category_name_zh CHECK (length(name_zh) <= 64),
    CONSTRAINT ck_category_name_en CHECK (length(name_en) <= 128)
);

-- ENT-002 源规则（最小单元：品类×大区×信源→状态+依据）
CREATE TABLE IF NOT EXISTS rule (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    category_id INTEGER NOT NULL REFERENCES category(id),
    region      TEXT    NOT NULL,   -- 枚举见 OD 字典 §2 region
    source_type TEXT    NOT NULL,   -- 枚举见 OD 字典 §2 source_type
    rule_status TEXT    NOT NULL,   -- 枚举见 OD 字典 §2 rule_status
    basis_text  TEXT    NOT NULL,   -- 依据（GBR-004 必填，样例数据带「样例」前缀）
    note        TEXT,               -- 备注，可空
    operator    TEXT    NOT NULL,   -- 登记人/最近修订人（无账号体系，文本）
    created_at  TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%S','now','localtime')),
    updated_at  TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%S','now','localtime')),
    CONSTRAINT uq_rule_entry UNIQUE (category_id, region, source_type),   -- FR007-P1 查重落点
    CONSTRAINT ck_rule_region  CHECK (region IN ('EU','NA','ME','SEA','OTHER')),
    CONSTRAINT ck_rule_source  CHECK (source_type IN ('POLICY','CUSTOMS','LOGISTICS','CARRIER','PORT')),
    CONSTRAINT ck_rule_status  CHECK (rule_status IN ('ACCEPTABLE','CONDITIONAL','FORBIDDEN')),
    CONSTRAINT ck_rule_basis   CHECK (length(basis_text) <= 500 AND length(basis_text) > 0),
    CONSTRAINT ck_rule_note    CHECK (note IS NULL OR length(note) <= 200),
    CONSTRAINT ck_rule_operator CHECK (length(operator) <= 32 AND length(operator) > 0)
);

-- ENT-003 变化记录（append-only）
CREATE TABLE IF NOT EXISTS change_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    rule_id     INTEGER NOT NULL REFERENCES rule(id),
    old_status  TEXT    NOT NULL CHECK (old_status IN ('ACCEPTABLE','CONDITIONAL','FORBIDDEN')),
    new_status  TEXT    NOT NULL CHECK (new_status IN ('ACCEPTABLE','CONDITIONAL','FORBIDDEN')),
    basis_text  TEXT    NOT NULL CHECK (length(basis_text) <= 500 AND length(basis_text) > 0),
    operator    TEXT    NOT NULL CHECK (length(operator) <= 32 AND length(operator) > 0),
    changed_at  TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%d %H:%M:%S','now','localtime'))
);

-- 库级 append-only 防线（第二层，第一层是 API 面无端点，见跨模块专项 01）
CREATE TRIGGER IF NOT EXISTS trg_change_log_no_update
BEFORE UPDATE ON change_log
BEGIN SELECT RAISE(ABORT, 'change_log is append-only (GBR-003)'); END;

CREATE TRIGGER IF NOT EXISTS trg_change_log_no_delete
BEFORE DELETE ON change_log
BEGIN SELECT RAISE(ABORT, 'change_log is append-only (GBR-003)'); END;
```

### 4.2 字段说明（对齐全局方案 §4）

三表字段名与 ENT-001/002/003 **逐字段同名同义**（name_zh/name_en/region/source_type/rule_status/basis_text/note/operator/created_at/updated_at/rule_id/old_status/new_status/changed_at），长度与必填口径一致；无自增实体字段之外的增删。时间统一存本地时间文本 `YYYY-MM-DD HH:MM:SS`（秒级入库保证排序稳定，展示到分钟由前端/M03 格式化，满足 FR006-R1）。

### 4.3 枚举对齐 OD 字典 §2（真源引用，不复制语义）

| 字段 | 枚举值（存储码） | 中文（展示，取自 M03 常量表，不落库） |
|------|------------------|--------------------------------------|
| rule_status | ACCEPTABLE / CONDITIONAL / FORBIDDEN | 可接 / 敏感（条件接） / 不可接 |
| source_type | POLICY / CUSTOMS / LOGISTICS / CARRIER / PORT | 国家政策 / 海关 / 头部物流 / 船司 / 目的港 |
| region | EU / NA / ME / SEA / OTHER | 欧洲 / 北美 / 中东 / 东南亚 / 其他 |

枚举变更 = OD 字典变更，回上游走确认；本项目不建字典表（五值固定枚举，CHECK 约束即字典落地）。

## 5. 索引设计

| 表 | 索引 | 字段组合 | 服务的查询 |
|----|------|----------|-----------|
| rule | `idx_rule_entry` | (category_id, region) | 展示条目聚合（品类×大区分组，M03 合并输入）、下钻列表 |
| rule | `idx_rule_region` | (region) | 大区矩阵聚合、/api/regions/{code}/rules |
| rule | `idx_rule_updated` | (updated_at) | PD-004 列表默认「更新时间倒序」 |
| change_log | `idx_change_rule` | (rule_id) | FR-008 AT-004 规则历史查询、时间线关联 JOIN |
| change_log | `idx_change_time` | (changed_at) | 时间线倒序扫描（FR006-R1） |
| category | UNIQUE 约束隐含索引 ×2 | name_zh / name_en(NOCASE) | FR-007 判重复用、/api/search 双向匹配 |

量级说明：种子数据 ≤ 数百行，索引为口径完备性设计（全部命中 §M02 查询路径），非性能兜底。

## 7. SQL 脚本与数据变更策略

| 项目 | 约束 | 说明 |
|------|------|------|
| 初始建表 | `database/schema.sql`（DDL，含触发器） | `scripts/init_db.sh`：删旧库→执行 schema→执行 seed（幂等=重建） |
| 种子数据 | `database/seed.py`（DML） | 与 DDL 分离；内容见 M05 |
| 表结构变更 | v1.0.0 无迁移体系 | 单版本闭环：变更=重建库+重播种（样例系统数据无保全价值）；真实迁移需求后续版本评估 |
| 历史数据迁移 | 不适用 | 首版无历史库 |
| 连接规约 | db.py 每连接执行 `PRAGMA foreign_keys=ON`（SQLite 默认关） | 外键强制在连接层保证，非建库层 |

## 8. 风险与待确认项

| 项目 | 内容 | 等级 | 处置 |
|------|------|------|------|
| changed_at 秒级同秒排序 | 同秒多条修订理论可能，倒序不稳定 | 低 | 排序追加 id DESC 次序键（写入 M02 §4.5 查询规约） |
| name_en 唯一性 NOCASE | SQLite NOCASE 仅 ASCII 大小写折叠 | 低 | 英文名样例均为 ASCII；非 ASCII 混名场景留待真实数据出现再评估 |

## 9. 核查结论

1. ENT→表完整映射：三表逐字段对齐全局方案 §4，无遗漏无新增业务字段。
2. 枚举三处一致：CHECK 约束 = OD 字典 §2 = M03 常量表键（Task-002 验收含一致性断言）。
3. 可稳定推导 SQL：DDL 定版即可直接执行；append-only 在库级有触发器防线。

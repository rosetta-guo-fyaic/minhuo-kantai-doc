## 1. 基础信息与通用规约

| 项 | 定版 |
|----|------|
| 路由实现 | FastAPI（`backend/app/api.py`），前缀 `/api` |
| 端点总数 | **8 个**（§2~§5 逐个定义）；完整路由清单见 §7（FR-008 无绕过证明的枚举真源） |
| 数据格式 | 请求/响应均为 `application/json`（q 等查询参数除外） |
| 时间格式 | 出参 `YYYY-MM-DD HH:MM`（分钟级，由存储秒级截断）；日期 `YYYY-MM-DD` |
| 错误响应体 | `{"error": {"code": "<错误码>", "message": "<技术性说明>", "detail": {<可选字段>}}}` |
| 入参校验 | 全部端点 Pydantic 模型：类型/必填/长度（64/128/500/200/32）/枚举白名单（OD 字典 §2） |
| SQL 规约 | 一律参数占位符；LIKE 查询先转义 `%` `_` `\`（防注入+防通配符注入） |
| 状态计算 | 只读端点一律调用 M03 模块产出合并态；路由层禁止出现状态比较逻辑（FR003-R5） |

## 2. 只读端点一：GET /api/overview（三态统计，FR-001）

| 项 | 定义 |
|----|------|
| 用途 | PD-001 三张统计卡片；计数=**展示条目**（品类×大区，就严合并后）归入三态，N1+N2+N3=展示条目总数（GBR-001） |
| Query 参数 | `region?`（枚举）、`source_type?`（枚举）、`status?`（枚举）——与 /api/rules 同参，卡片随筛选联动重算（FR001-R1） |
| 处理 | M03 `build_display_entries(filters)` → 计数（`status` 参数作用于合并后的条目态，先算后筛 FR002-R3） |

成功响应 `200`：

```json
{ "counts": { "ACCEPTABLE": 12, "CONDITIONAL": 5, "FORBIDDEN": 7 }, "total": 24, "empty": false }
```

（空库/筛选无结果时三值均为 0、`empty:true`，前端据此显示空态，EX-FR001-01/EX-FR002-01。）

## 3. 只读端点二~五

### 3.1 GET /api/rules（筛选列表，FR-002 + FR-007 检索）

| 项 | 定义 |
|----|------|
| 用途 | 双粒度：PD-001 展示条目列表（merged，默认）与 PD-004 源规则检索列表（source，供修订定位） |
| Query 参数 | `granularity=merged|source`（默认 merged）；`region?`、`source_type?`、`status?`（筛选语义同 §2，信源单选即单源口径 FR002-R2/FR003-R4）；`q?`（品类关键字，中英双向子串包含，PD-004 检索用，复用 §5 匹配与转义口径）；`sort?`（merged 默认 `name_zh`、source 默认 `-updated_at`） |

merged 响应 `200`（截取）：

```json
{ "items": [ {
    "category": { "id": 1, "name_zh": "锂电池", "name_en": "Lithium Battery" },
    "region": "EU",
    "merged_status": "FORBIDDEN", "conflict": true,
    "basis_digest": "船司公告：锂电池欧盟航线暂停承接（样例）",
    "updated": "2026-10-20",
    "sources": [ { "id": 11, "source_type": "POLICY", "rule_status": "CONDITIONAL",
                   "basis_text": "…全文…", "operator": "关务-张明", "updated_at": "2026-10-18 14:30" } ]
} ], "total": 24 }
```

要点：`merged_status/conflict/basis_digest` 由 M03 计算（digest=最严源依据 40 字截断 FR002-R4）；`sources[]` 含源规则 `id`——PD-004 修订面板据此调用 PUT。source 粒度返回逐条源规则全字段（含 note/created_at），字段集=FR-005 §3.1 同源。

### 3.2 GET /api/regions/matrix（大区矩阵，FR-004）

| 项 | 定义 |
|----|------|
| 用途 | PD-002 五行×三态+合计矩阵；无信源筛选场景（FR004-R2），不收 source_type |
| 处理 | 全量展示条目按合并态聚合计数（冲突条目计入就严列） |

响应 `200`（行序固定 = OD 字典 region 序）：

```json
{ "rows": [ { "region": "EU", "region_zh": "欧洲",
              "counts": { "ACCEPTABLE": 3, "CONDITIONAL": 2, "FORBIDDEN": 4 }, "total": 9 } ] }
```

（`region_zh` 取自 M03 常量表；空区全 0，行仍返回，可点击 FR004-R3。）

### 3.3 GET /api/regions/{code}/rules（下钻明细，FR-005）

| 项 | 定义 |
|----|------|
| 用途 | PD-002 下钻区：选定大区的全部展示条目 |
| Path 参数 | `code` ∈ region 枚举，非法 → `404 MH-404-NOT_FOUND` |
| Query 参数 | `source_type?`、`status?`（区内二次筛选，复用 FR002-R2/R3 同一规则 FR005-R3） |

响应 `200`：`{"region": "EU", "items": [...]}`，items 元素同 §3.1 merged 结构，另带 `source_display`（无信源筛选=「合并（N 源）」，单源口径=该信源中文名，FR-005 §3.1）与 `basis_full`（最严源依据全文）。空区返回空 items（前端显示「该大区暂无结构化规则」EX-FR004-01）。

### 3.4 GET /api/changes（变化时间线，FR-006）

| 项 | 定义 |
|----|------|
| 用途 | PD-003 时间线，只读 |
| Query 参数 | `category_id?`（整数）、`region?`（枚举）——两维单选过滤（FR006-R4）；**不提供**信源/状态筛选（范围外） |
| 排序 | `changed_at DESC, id DESC`（FR006-R1 + M01 §8 同秒次序键） |
| 关联完整性 | JOIN rule + category；孤儿记录（rule/category 缺失）不出现在结果并写 WARNING 日志（FR006-R3/EX-FR006-03，防御分支） |

响应 `200`（截取）：

```json
{ "items": [ { "id": 9, "changed_at": "2026-10-22 09:15",
               "category": { "id": 1, "name_zh": "锂电池" }, "region": "EU",
               "source_type": "CARRIER",
               "old_status": "CONDITIONAL", "new_status": "FORBIDDEN",
               "basis_text": "…修订依据全文…", "operator": "关务-张明" } ], "total": 10 }
```

（信源名展示「信源名 · 依据」由前端用常量表拼装；无任何写方法挂在本路径——证明见跨模块专项 01。）

## 4. 只读端点六：GET /api/search?q=（品名查询，FR-009）

| 项 | 定义 |
|----|------|
| 用途 | PD-005 品名查询 + 各页头部快捷搜索（跳转 `search.html?q=`） |
| Query 参数 | `q`：必填；去首尾空格后非空、≤64 字符；空/超长 → `400 MH-400-VALIDATION` |
| 匹配口径 | `name_zh LIKE '%q%' OR name_en LIKE '%q%' COLLATE NOCASE`（中英双向子串、英文忽略大小写，FR009-M1/QL-005）；q 中 `%`/`_`/`\` 先经 ESCAPE 转义 |
| 结果结构 | 命中品类 × 大区分组，组内条目=展示条目（M03 合并态+冲突标注+最严依据摘要+sources 供展开，FR009-M2） |
| 截断 | 命中品类 >50 → 仅返回前 50 组 + `truncated:true`（FR009-M3）；无命中 → 空 items（**不返回任何猜测/近似结果**，无命中文案由前端常量表渲染，FR009-O1/GBR-006） |

响应 `200`（截取）：

```json
{ "q": "锂电", "total_matched": 1, "truncated": false,
  "categories": [ { "category": { "id": 1, "name_zh": "锂电池", "name_en": "Lithium Battery" },
    "regions": [ { "region": "EU", "merged_status": "FORBIDDEN", "conflict": true,
                   "basis_digest": "…", "sources": [ …同 §3.1… ] } ] } ] }
```

## 5. 写端点：POST /api/rules 与 PUT /api/rules/{id}

### 5.1 POST /api/rules（登记，FR-007）

请求体（Pydantic 模型 `RuleCreate`）：

| 字段 | 类型 | 必填 | 校验（FR007-V1~V5） |
|------|------|------|---------------------|
| name_zh | str≤64 | 是 | 非空；同名既有品类（精确）则复用 |
| name_en | str≤128 | 是 | 非空；判重忽略大小写，命中即复用 |
| region / source_type | 枚举 | 是 | 白名单（OD 字典 §2） |
| rule_status | 枚举 | 是 | 白名单；**缺省值 ACCEPTABLE**（FR007-V5 默认可接） |
| basis_text | str≤500 | 是 | 非空（GBR-004） |
| note | str≤200 | 否 | — |
| operator | str≤32 | 是 | 非空 |

处理（单事务）：①品类解析（TD-01：name_zh 精确命中或 name_en 忽略大小写命中 → 复用该品类；均未命中 → 自动建档 FR007-P2）→ ②查 `(category_id, region, source_type)`：已存在 → `409 MH-409-DUPLICATE`，detail 返回 `{existing_rule_id, existing_status}` 供前端「转修订」定位（FR007-P1）→ ③INSERT rule。**不写 change_log**（FR007-P3 登记不留痕）。

成功 `201`：返回新建源规则全字段 JSON。失败（库异常）→ `500 MH-500-INTERNAL`，事务回滚，表单数据保留在前端（EX-FR007-03）。

### 5.2 PUT /api/rules/{id}（修订+自动留痕，FR-008；事务细节见跨模块专项 01）

请求体（`RuleRevise`）：

| 字段 | 类型 | 必填 | 校验（FR008-V1~V3） |
|------|------|------|---------------------|
| new_status | 枚举 | 是 | 白名单；前端预选当前状态 |
| basis_text | str≤500 | 是 | 非空、不预填旧依据 |
| operator | str≤32 | 是 | 非空 |

处理（**单 SQLite 事务**，GBR-002 无绕过）：

```text
BEGIN
  SELECT rule WHERE id=?          → 无此行：404 MH-404-NOT_FOUND（事务外）
  new_status == 当前状态           → 422 MH-422-NO_CHANGE（无变化不留痕，FR008-P1，事务外拦截）
  UPDATE rule SET rule_status=?, basis_text=?, operator=?, updated_at=now WHERE id=?
  INSERT change_log(rule_id, old_status, new_status, basis_text, operator, changed_at=now)
COMMIT（任一步异常 → ROLLBACK，规则与留痕同生共死，EX-FR008-03）
```

成功 `200`：`{"rule": <更新后全字段>, "change_id": <新增变化记录 id>}`（前端提示「修订成功，已自动生成变化记录」+ PD-003 跳转）。

## 6. 技术口径决策（TD，供 PM/PD 评审确认）

| 编号 | 决策 | 理由 |
|------|------|------|
| TD-01 | 品类解析顺序：name_zh 精确命中 > name_en 忽略大小写命中 > 建档；若两者命中**不同**品类 → `400 MH-400-VALIDATION`（detail 提示档案冲突，需先在库内统一） | FR-007 只说「命中即复用」，双名分别命中不同档无定义；拦截最保守，不改需求只补分支 |
| TD-02 | `status` 筛选一律作用于「当前口径的条目状态」（先算后筛），单信源口径下作用于该信源状态 | FR002-R3 + 全局方案 §3.2 的直接落地 |
| TD-03 | 错误 message 为技术性英文短语，用户可见文案（「请填写{字段名}」等）由前端按 code+字段从常量表渲染 | PD 硬要求③文案单点的自然推论 |

### 7.2 错误码表（四号仓库断言锚点）

| 错误码 | HTTP | 触发场景 | 前端表现（文案出自常量表） |
|--------|------|----------|---------------------------|
| MH-400-VALIDATION | 400 | 入参缺失/超长/枚举外/空 q/TD-01 档案冲突 | 「请填写{字段名}」/「品名过长」+ 高亮 |

| MH-500-INTERNAL | 500 | 库异常/事务回滚（EX-FR007-03/EX-FR008-03） | 「登记失败，请重试」/「修订失败，请重试」 |

## 8. 核查结论

1. FR-001~009 每条功能都有端点承接（§7.1 映射列无空格）；无范围外端点（无 DELETE/PATCH、无 change_log 写端点、无用户/权限/导出/采集端点）。
2. 全部入参有 Pydantic 校验；全部 SQL 参数化；LIKE 已转义。
3. 只读端点全部经 M03 单点计算，路由层无状态比较逻辑（Task-004 验收含 grep 断言）。

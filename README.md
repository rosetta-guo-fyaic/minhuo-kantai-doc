# 项目仓库模板

## 1. 目录定位

`<TOOL_REPO_ROOT>/00_项目仓库模板/` 用于提供“单个具体系统项目”的标准研发仓库骨架。

该目录不是项目实例集合，也不是工具真源目录，而是用于生成项目仓库的模板结构。

## 2. 使用范围

本模板适用于：

1. 新系统项目启动
2. 既有系统重建标准研发工作区
3. 需要统一 OD 工作区、零号仓库、一号仓库、二号仓库、三号仓库、四号仓库结构的项目

## 3. 核心原则

1. 一个项目仓库只服务一个具体系统项目。
2. 当前模板只提供目录骨架和说明文件，不复制工具真源正文。
3. 规范、模板、AI 工作站、方法论、标准词典、宏观架构等内容统一引用当前标准仓库中的工具真源目录。
4. 项目级内容只能在项目仓库内沉淀，不得回写工具真源正文。
5. `README.md` 与 `项目仓库操作说明.md` 只承载结构说明、使用说明和阶段门禁，不承载项目正式正文真源。
6. 上述说明文件属于工具仓托管说明文件；标准仓库更新后，允许由安装脚本同步覆盖到真实项目仓库。
7. 当前 `00_项目仓库模板/` 默认只承接项目文档仓骨架，不承接独立代码仓骨架；代码仓后续应由独立代码仓模板承接。

## 5. 各层职责

1. `00_OD工作区/`
   用于承接项目正式进入零号仓库前的业务输入、To-Be 流程、组织分工、权限矩阵和项目级字典补充。

2. `01_零号仓库/`
   用于承接项目启动、准入、范围和环境层面的项目管理产物。

3. `02_一号仓库/`
   用于承接原始输入、调研整理、需求分析和需求确认。

4. `03_二号仓库/`
   用于承接产品方案设计、原型设计、PRD 和产品基线。

5. `04_三号仓库/`
   用于承接技术方案、技术评审门禁、研发实施编排和研发验证交接输入。

6. `05_四号仓库/`
   用于承接测试验收、系统运维、产品运营和交付支撑。

## 7. 使用入口

首次基于本模板创建真实项目仓库时，建议按以下顺序阅读和修改：

1. 根 `README.md`
2. `项目仓库操作说明.md`
   - 其中优先关注需求变更、新版本启动和 `hotfix` 的场景说明
3. `00_OD工作区/README.md`
4. `01_零号仓库/README.md`
5. `02_一号仓库/README.md`
6. `03_二号仓库/README.md`
7. `04_三号仓库/README.md`
8. `05_四号仓库/README.md`

## 8. 按阶段推进的推荐顺序

建议按以下顺序推进项目仓库工作，而不是并行无序填充所有目录：

1. `00_OD工作区/`
   先补方法论、To-Be 流程、组织分工、权限矩阵和项目级补充字典。
2. `01_零号仓库/`
   先把项目核准、需求池、项目环境和产品路标写清楚。
3. `02_一号仓库/`
   再把原始输入、待确认问题和需求分析做扎实。
4. `03_二号仓库/`
   再进入正式产品设计，形成方案、原型、PRD、产品基线，以及新版本承接或基线后正式变更结论。
5. `04_三号仓库/`
   再把产品设计转换为技术方案正文、技术评审门禁事实、实施编排输入和研发交接输入。
6. `05_四号仓库/`
   最后进入测试验收、系统运维、产品运营和交付执行。

## 9. 阶段门总览

| 阶段 | 主要目标 | 进入下一阶段前至少要具备什么 |
|------|----------|------------------------------|
| `00_OD工作区` | 形成项目前置共识 | 方法论口径、To-Be 流程、组织分工、权限矩阵和关键字典已有初稿 |
| `01_零号仓库` | 明确项目启动与准入 | 项目核准、范围边界、环境准备、需求池与路标已初步明确 |
| `02_一号仓库` | 把需求说清楚 | 需求分析结论、待确认清单、用户故事、URD 和版本需求确认结果已稳定 |
| `03_二号仓库` | 把产品设计清楚 | 方案、原型、PRD、产品基线以及关键设计追溯关系已形成，并能区分新版本承接、基线后正式变更与 `hotfix` |
| `04_三号仓库` | 把技术方案和研发输入设计清楚 | 技术方案正文、技术评审门禁、实施编排和研发交接输入已收敛 |
| `05_四号仓库` | 完成测试验收、交付、运维与运营支撑 | 版本测试验收、交付、运维和运营执行材料已齐套 |

## 10. 推荐阅读与使用方式

对于首次接触项目仓库模板的使用者，建议这样使用：

1. 先看根 `README.md`，建立阶段全景。
2. 再看 `项目仓库操作说明.md`，确认 AI 使用方式与常见场景操作路径，尤其是需求变更、新版本启动与 `hotfix` 的判断口径。
3. 然后逐仓阅读各阶段 `README.md`，理解每个阶段的输入、输出和门禁。
4. 最后进入各子目录 `README.md`，按建议内容开始沉淀正式产物。

补充说明：

1. 项目仓库初始化已由安装脚本和 AI 结构检查链路承接。
2. 产品经理在真实项目仓库中不需要手工按模板执行初始化动作。

## 11. 禁止事项

1. 不得在本模板目录中复制规范正文。
2. 不得在本模板目录中复制模板正文。
3. 不得在本模板目录中复制 AI 工作站正文。
4. 不得把项目实例直接长期维护在本模板目录中。

## 12. AI 结构检查提醒

任何 AI 在真实项目仓库中开展正式工作前，都应先按 `<TOOL_REPO_ROOT>/06_工作规范/01_治理与基础规范/02_项目仓库结构检查与初始化规范.md` 和 `<TOOL_REPO_ROOT>/08_AI工作站/00_AI工作总则/03_AI项目仓库结构检查规则.md`，检查当前工作区结构是否与本模板一致。

## 13. 一句话说明

**项目仓库模板负责提供单项目骨架，工具真源目录负责提供公共规则与能力。**

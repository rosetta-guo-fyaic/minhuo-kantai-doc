# 需求分析

`03_需求分析/` 是一号仓库的正式需求分析输出区。

本目录用于沉淀：

1. 项目级需求管理总览
2. 用户故事
3. 需求补充材料
4. URD

## 1. 目录定位

这里是一号仓库进入二号仓库前的正式需求分析真源层。

它解决的是：

1. 哪些需求已经完成确认并进入正式分析表达
2. 哪些内容应沉淀为用户故事、项目级总览、补充分析材料和 URD
3. 二号仓库 `01_方案设计/` 应该直接读取哪些正式上游输入

它不是：

1. 原始调研资料区
2. 待确认事项区
3. 方案设计区
4. 原型或页面设计区

## 2. 预置边界

以下正式正文文件不在模板仓预置，应由真实项目仓库中的 Skill 按需生成：

1. `00_需求管理总览.md` 不在模板仓预置，应由 Skill 基于 `<TOOL_REPO_ROOT>/07_公共模板库/03_一号仓库模板/01_需求管理总览模板.md` 生成。
2. `03_URD.md` 不在模板仓预置，应由 Skill 基于 `<TOOL_REPO_ROOT>/07_公共模板库/03_一号仓库模板/05_URD模板.md` 生成。
3. `02_需求补充材料/` 属于正式需求分析补充附件区，用于承接已经确认、但不适合直接写入单条用户故事或 `03_URD.md` 主体的正式补充分析内容。
4. `02_需求补充材料/` 下的正式文件，应优先基于 `<TOOL_REPO_ROOT>/07_公共模板库/03_一号仓库模板/10_需求补充材料模板.md` 生成，并显式回指关联 `REQ-*`、`US-*`、`AC-*` 或 `03_版本需求确认/vX.Y.Z/`。
5. `01_用户故事/` 下的 `US-*.md` 应由 Skill 基于 `<TOOL_REPO_ROOT>/07_公共模板库/03_一号仓库模板/04_用户故事模板.md` 生成。

## 3. 内部职责分工

1. `00_需求管理总览.md`
   - 项目级需求分析入口
   - 负责管理分析边界、需求索引、用户故事索引、调研索引和协作进度
2. `01_用户故事/`
   - 用户故事真源层
   - 负责承接单条 `REQ-*` 拆解后的 `US-*` 正式正文
3. `02_需求补充材料/`
   - 正式补充分析附件层
   - 负责沉淀跨故事共用规则、边界、口径、角色差异和历史约束
4. `03_URD.md`
   - 项目级正式需求分析主文档
   - 负责整合用户故事、范围、流程、角色、数据和非功能要求

## 4. 进入条件

进入本目录前，至少应满足：

1. `02_需求确认/` 已完成本轮需求确认收口
2. 待确认事项未关闭的内容已显式挂牌，不再混入正式正文
3. 已确认需求专题、版本需求确认和确认记录中需要回写的内容已经稳定

## 5. 与二号仓库的关系

二号仓库正式承接的上游输入，仍然直接以本目录为主。

当前承接原则为：

1. 二号仓库 `01_方案设计/` 直接引用本目录正式真源
2. 不再创建二号仓库 `03_需求分析/` 镜像目录
3. `README.md`、临时稿、草稿和无追溯文件，不属于正式承接输入

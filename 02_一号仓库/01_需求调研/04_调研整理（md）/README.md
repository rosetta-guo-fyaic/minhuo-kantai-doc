# 调研整理（md）说明

## 1. 目录定位

`01_需求调研/04_调研整理（md）/` 是一号仓库的调研整理区。

这里用于把 `01_原始资料/`、`02_需求问卷/`、`03_调研记录/` 中的内容，转成可阅读、可追问、可继续确认的 Markdown 资料。

典型产物包括：

1. 基础信息清单
2. As-Is 流程转写稿
3. To-Be 目标流程整理稿
4. 调研纪要整理稿
5. 问卷回收整理稿
6. 初步问题与观察记录

## 2. 与上下游目录的关系

本目录位于调研阶段中间层，承上启下：

```text
01_原始资料 / 02_需求问卷 / 03_调研记录
-> 04_调研整理（md）
-> 05_调研结论与待转确认项
-> 02_需求确认
```

它解决的是“原始材料如何被整理”，还不是“正式需求如何确认和分析”。

## 3. 使用规则

1. 本目录只存 Markdown 整理稿，不存原始二进制附件
2. 每份整理稿都应尽量能追溯回原始资料、问卷或调研记录来源
3. 可以在这里做摘录、归纳、结构化整理和问题标注
4. 执行原始文档整理时，默认产物必须是完整结构化整理稿，不得只输出摘要、概要或几条结论
5. 允许重组正文结构，但不允许删掉原始资料中的主体事实、关键步骤和关键限制条件
6. 这里不直接生成正式 `REQ`、`US`、`URD`
7. 若信息仍不完整，应优先转入 `05_调研结论与待转确认项/` 或 `02_需求确认/01_待确认需求/`
8. 本目录整理稿不能直接作为二号仓库承接输入，必须先经过 `02_需求确认/`

## 4. 文件组织建议

建议按主题化方式命名：

1. `基础信息整理_主题.md`
2. `流程整理_主题.md`
3. `访谈整理_主题.md`
4. `问卷结果整理_主题.md`
5. `问题观察_主题.md`

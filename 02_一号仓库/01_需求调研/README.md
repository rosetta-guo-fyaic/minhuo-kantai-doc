# 需求调研

## 1. 目录定位

`01_需求调研/` 是一号仓库的调研输入层。

它用于承接产品经理在需求分析前补充形成的调研材料，把原始输入逐步沉淀为可进入 `02_需求确认/` 的调研结论与待确认事项。

一句话理解：

这里解决的是“产品经理补充调研的信息如何被收集、记录、整理和转确认”。

## 2. 五层结构定位

`01_需求调研/` 当前固定分为五层：

1. `01_原始资料/`
   - 原件保真层
   - 解决“原始资料从哪里来”
2. `02_需求问卷/`
   - 调研准备层
   - 解决“调研前准备问什么、验证什么”
3. `03_调研记录/`
   - 调研过程留痕层
   - 解决“调研过程中实际说了什么、看到了什么”
4. `04_调研整理（md）/`
   - 结构化转写层
   - 解决“原始资料如何被整理成可继续分析的 Markdown 材料”
5. `05_调研结论与待转确认项/`
   - 调研收口桥接层
   - 解决“哪些内容已经形成初步结论，哪些内容需要转入正式需求确认”

## 3. 推荐使用顺序

```text
01_原始资料
-> 02_需求问卷
-> 03_调研记录
-> 04_调研整理（md）
-> 05_调研结论与待转确认项
-> 02_需求确认
```

说明：

1. `01` 到 `03` 属于调研输入与调研过程层。
2. `04` 是调研整理的正式中间层，也是 AI 最主要的整理层。
3. `05` 不是长期正式真源，只是进入 `02_需求确认/` 前的桥接层。

## 4. 输入与输出边界

### 4.1 上游输入

本目录主要承接：

1. 业务方补充提供的原件、附件、截图、录音、文档
2. 产品经理为调研准备的问题清单、问卷、访谈提纲
3. 产品经理在访谈、会议、现场沟通中形成的过程记录
4. `00_OD工作区/` 未能直接进入 `02_需求确认/` 的补充调研主题和验证动作

### 4.2 下游输出

本目录的下游不是 `03_需求分析/`，而是优先进入 `02_需求确认/`。

正式收口方式应为：

1. 已识别出的需求对象
   - 进入 `02_需求确认/00_需求清单.md`
2. 仍待确认的事项
   - 进入 `02_需求确认/01_待确认需求/02_待确认清单.md`
3. 与确认事项配套的说明材料
   - 进入 `02_需求确认/01_待确认需求/`

## 5. 预置边界

本目录在模板仓中只预置目录结构与说明文件，不预置真实项目正文。

真实项目仓库中，以下内容应由产品经理或 Skill 按需生成：

1. `02_需求问卷/` 下的调研前准备件
2. `03_调研记录/` 下的 `SRV-*` 调研记录
3. `04_调研整理（md）/` 下的结构化整理稿
4. `05_调研结论与待转确认项/` 下的桥接稿

## 6. 使用规则

1. 不得把 `01_需求调研/` 中的原件、问卷、记录或整理稿，直接当作正式需求分析真源。
2. 原始附件不得跳过 `04_调研整理（md）/` 直接写成 `REQ`、`US` 或 `URD`。
3. `05_调研结论与待转确认项/` 中的内容，最终必须转入 `02_需求确认/` 的正式主表或主清单，不得长期停留为并行真源。
4. 同一主题若同时存在原件、调研记录、整理稿和结论稿，应显式保持来源可追溯。
5. 若信息仍不完整，应先保留在调研层或转入待确认区，而不是提前写成已确认事实。
6. `SRV-*` 仅用于调研记录与来源追溯，不作为正式需求对象编号。
7. `05_调研结论与待转确认项/` 不得绕过 `02_需求确认/` 直接进入 `03_需求分析/`。

## 8. 文件组织建议

1. `01_原始资料/`
   - 允许原始 Word、Excel、PDF、PPT、图片、录音、录屏等原件
2. `02_需求问卷/`
   - 建议使用 `需求问卷_主题_日期.md`、`访谈提纲_主题_日期.md`
3. `03_调研记录/`
   - 建议一次调研活动一份记录，使用 `SRV-*` 编号
4. `04_调研整理（md）/`
   - 建议按 `基础信息整理_主题.md`、`流程整理_主题.md`、`访谈整理_主题.md` 等主题化命名
5. `05_调研结论与待转确认项/`
   - 建议控制为总览稿和少量专题桥接稿，不在这里铺设长期主表

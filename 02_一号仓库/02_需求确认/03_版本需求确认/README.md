# 版本需求确认说明

`03_版本需求确认/` 用于承接各正式版本的需求确认、版本范围口径和版本需求变更确认，是一号仓库向二号仓库移交前的重要收口层。

## 1. 目录定位

本目录重点解决以下问题：

1. 哪些需求进入当前版本
2. 哪些需求暂不进入当前版本
3. 当前版本范围何时冻结、冻结后如何变更
4. 本轮版本范围与上一轮相比有哪些差异

## 2. 与其他产物的关系

1. 上游来自 `00_需求清单.md` 中已确认且可纳入版本讨论的需求
2. 必要时引用 `02_已确认需求/` 的专题结论
3. 下游用于支撑 `03_需求分析/` 和二号仓库方案设计的版本边界
4. 不得把未确认需求直接写成版本冻结结论

## 3. 产物形式

本目录不在模板仓中预置真实版本文件正文，但应在真实项目仓库中按正式版本建立对应目录。

真实项目仓库中，建议按以下结构生成：

```text
03_版本需求确认/
├── v1.0.0/
│   ├── 00_版本需求清单.md
│   └── 01_版本需求变更确认.md
└── v1.1.0/
    ├── 00_版本需求清单.md
    └── 01_版本需求变更确认.md
```

对应模板真源：

1. `<TOOL_REPO_ROOT>/07_公共模板库/03_一号仓库模板/12_版本需求清单模板.md`
2. `<TOOL_REPO_ROOT>/07_公共模板库/03_一号仓库模板/13_版本需求变更确认模板.md`

补充说明：

1. `00_版本需求清单.md` 可由一号仓库 Skill 基于已确认需求收口生成。
2. `01_版本需求变更确认.md` 是后续发生正式版本范围变化时的人工作业真源，AI 只能读取、引用和校验，不得自动生成。

## 4. 使用规则

1. 版本确认文件应明确列出纳入范围与排除范围
2. 应明确当前版本冻结时间点和冻结后变更规则
3. 若仍有高风险待确认项未关闭，应显式挂牌说明
4. 进入二号仓库前，应以本目录中的版本确认结论作为版本口径依据
5. 历史版本目录不得删除或覆盖
6. 若版本范围已发生正式变化，不得只改 `00_需求清单.md` 主表而不更新本目录

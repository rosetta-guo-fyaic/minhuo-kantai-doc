# 确认记录说明

## 1. 目录定位

`02_需求确认/01_待确认需求/04_确认记录/` 用于沉淀需求确认阶段的正式确认过程留痕。

它承接的不是普通沟通草稿，而是已经发生的会议确认、访谈确认、回执确认和决策确认记录。

本目录的核心作用有三点：

1. 把某次确认动作的对象、过程和结论留痕下来
2. 为 `02_待确认清单.md` 的状态更新和结论回写提供依据
3. 为 `00_需求清单.md`、`02_已确认需求/`、`03_版本需求确认/` 和 `03_需求分析/` 的更新提供追溯链路

## 2. 它与其他文件的关系

建议按以下关系理解：

```text
上游：
├── 03_业务追问/
├── 02_待确认清单.md
├── 01_需求调研/05_调研结论与待转确认项/
└── 00_OD工作区/ 输入材料

04_确认记录/CR-*.md
│
├── 回写 00_需求清单.md
├── 回写 02_待确认清单.md
├── 必要时支撑 02_已确认需求/AC-*.md
├── 必要时支撑 03_版本需求确认/vX.Y.Z/
└── 稳定后进入 03_需求分析/
```

## 3. 什么时候生成

出现以下场景时，建议生成确认记录：

1. 某次确认动作已经形成明确结论，需要正式落档
2. 一次确认同时关闭多条 `QL-*`，或影响多个 `REQ-*`
3. 某个业务规则、角色权限口径、流程例外需要保留确认依据
4. 后续预计会有人追问“这项结论是谁在什么场景下确认的”

不建议把以下内容直接当确认记录：

1. 尚未达成一致的零散聊天
2. 尚未转成正式结论的草稿纪要
3. 仅用于个人理解的临时笔记

## 4. 生成方式

本目录文件不在模板仓预置正文，应在真实项目仓库中按需生成。

对应模板真源：

1. `<TOOL_REPO_ROOT>/07_公共模板库/03_一号仓库模板/11_确认记录模板.md`

建议命名方式：

1. `CR-01_{主题}确认记录.md`
2. `CR-02_{主题}确认记录.md`

## 5. 生成后必须做的回写动作

确认记录生成后，不应停留在“留个纪要”。

至少需要检查以下回写动作：

1. `02_待确认清单.md` 中对应 `QL-*` 是否更新状态、结论和回写位置
2. `00_需求清单.md` 中对应 `REQ-*` 是否更新确认状态、范围或说明
3. 若该主题已形成稳定规则，是否需要沉淀到 `02_已确认需求/AC-*.md`
4. 若该结论影响版本纳入范围，是否需要同步进入 `03_版本需求确认/vX.Y.Z/`
5. 若该结论已经足够稳定，是否需要进入 `03_需求分析/` 的用户故事、补充材料或 URD

## 6. 使用原则

1. 确认记录管过程依据，不替代待确认主表
2. 待确认清单管问题状态，不替代确认过程全文
3. 已确认需求专题管稳定业务规则，不替代单次确认动作
4. 版本需求确认管版本收口，不替代单次确认记录

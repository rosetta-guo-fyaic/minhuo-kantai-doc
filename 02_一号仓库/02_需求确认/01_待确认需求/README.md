# 待确认需求说明

## 1. 目录定位

`02_需求确认/01_待确认需求/` 用于承接调研后、正式需求分析前仍需确认的需求事项。

它是：

1. 需求调研层到需求分析层之间的确认缓冲层
2. 业务事实尚未坐实前的临时记录区
3. 待确认清单、业务追问和确认记录的集中存放区

它不是：

1. 正式需求分析真源
2. 正式方案设计真源
3. 正式页面设计或原型真源

## 2. 推荐使用依据

本目录新增或修改文档时，建议优先参照：

1. `<TOOL_REPO_ROOT>/06_工作规范/04_需求分析规范/01_需求收集规范.md`
2. `<TOOL_REPO_ROOT>/06_工作规范/04_需求分析规范/02_需求分析规范.md`
3. `<TOOL_REPO_ROOT>/07_公共模板库/03_一号仓库模板/06_追问清单模板.md`
4. `<TOOL_REPO_ROOT>/08_AI工作站/01_AI能力模块/03_一号仓库能力模块/AM-01_需求分析器.md`

## 3. 主要内容

本目录主要放三类内容，建议按以下顺序理解：

1. `02_待确认清单.md`
   - 在真实项目仓库中由 Skill 基于一号仓库模板和项目实际内容生成
   - 用于登记待确认问题、责任人、确认方式和确认结论
2. `03_业务追问/`
   - 用于基于待确认清单继续登记业务追问、假设验证和补访问题
   - 它服务于待确认事项澄清，不替代待确认主表
3. `04_确认记录/`
   - 用于沉淀需求确认过程中的会议记录、确认纪要和回执材料
   - 在真实项目仓库中按需生成 `CR-*` 文件
   - 对应模板为 `<TOOL_REPO_ROOT>/07_公共模板库/03_一号仓库模板/11_确认记录模板.md`

## 4. 使用规则

1. 这里记录的是还没问清、还没确认、还没定稿的内容
2. 未确认的信息不要直接写进 `03_需求分析/` 的正式章节中
3. 一旦业务确认完成，应尽快把确认结果同步到 `00_需求清单.md` 和下游分析文档
4. 如果待确认项持续存在，应在移交二号仓库时显式挂牌，而不是默认忽略
5. `02_待确认清单.md` 不在模板仓预置，应在真实项目仓库中按需生成
6. `04_确认记录/` 中的文件用于留痕“确认动作本身”，生成后必须同步回写 `02_待确认清单.md`

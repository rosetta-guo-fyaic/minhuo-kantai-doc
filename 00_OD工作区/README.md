# OD工作区

## 1. 目录定位

`<PROJECT_ROOT>/00_OD工作区/` 是 OD 针对业务系统进行梳理后形成的业务原始需求输入区。

它承载的是项目在正式需求确认前的上游业务输入，不替代一号仓库正式需求真源，也不替代工具仓库中的标准真源目录。

一句话理解：

**OD 工作区负责把业务系统的上游输入先按 OD 的工作体系梳理清楚，供产品经理进入需求确认。**

## 2. 当前结构

```text
00_OD工作区/
├── README.md
├── 01_方法论/
├── 02_To-Be流程/
├── 03_组织分工/
├── 04_权限矩阵/
└── 05_字典/
```

## 3. 各目录职责

1. `01_方法论/`
   用于记录本项目在 OD 方法论工作体系下形成的方法论输入，包括方法论主文件、方法边界、规则来源和项目适配结论。这里承接的是项目方法论输入，不是 `<TOOL_REPO_ROOT>/09_DIC研发方法论/` 中的 DIC 系统研发方法论。

2. `02_To-Be流程/`
   用于记录业务目标流程、主流程、异常分支、审批点以及输入输出关系。

3. `03_组织分工/`
   用于记录业务相关部门、岗位、角色、职责边界和协作接口。

4. `04_权限矩阵/`
   用于记录业务权限边界、审批权限、数据范围和例外授权原则。

5. `05_字典/`
   用于记录术语、对象、状态、枚举以及项目级字典引用与补充口径。

## 4. 与方法论和工具真源的边界

1. `<PROJECT_ROOT>/00_OD工作区/01_方法论/` 承接的是项目方法论输入，需按 `<TOOL_REPO_ROOT>/06_工作规范/02_OD工作规范/` 中的方法论工作体系理解。
2. `<TOOL_REPO_ROOT>/09_DIC研发方法论/` 是 DIC 进行系统研发的方法论，用于指导零号到四号仓库如何开展研发工作，不是 `<PROJECT_ROOT>/00_OD工作区/01_方法论/` 的业务内容真源。
3. 标准词典上位真源在 `<TOOL_REPO_ROOT>/04_标准词典库/`，`<PROJECT_ROOT>/00_OD工作区/05_字典/` 只承载项目引用与项目补充。
4. OD 工作区只沉淀项目级原始需求输入和项目级补充结果，不替代标准真源目录。

进一步说明：

1. 这里可以写项目方法论输入、流程、组织、权限和字典的项目级结论，但不能改写工具仓库中的标准真源。
2. 这里可以写项目补充项、项目适配项和项目输入结果，但不能替代标准词典和正式工作规范。
3. 这里是原始需求输入层，不是正式需求分析层，也不是正式系统设计层。

## 5. 工具引用清单

建议优先引用以下工具真源：

1. `<TOOL_REPO_ROOT>/06_工作规范/02_OD工作规范/`
   用于引用 OD 工作区的工作体系、项目方法论输入口径、流程分类和字典结构规范。

2. `<TOOL_REPO_ROOT>/07_公共模板库/01_OD工作模板/`
   用于引用 OD 工作区各类输入模板、桥接模板，以及流程/组织/权限/字典的细化模板。

3. `<TOOL_REPO_ROOT>/04_标准词典库/`
   用于引用标准术语、角色名称、状态枚举和项目补充字典的上位真源。

4. `<TOOL_REPO_ROOT>/06_工作规范/`
   用于引用后续阶段会涉及的规则边界。

5. `<TOOL_REPO_ROOT>/09_DIC研发方法论/`
   仅用于帮助项目团队理解 OD 输出进入后续研发链路后的承接方式，不直接作为 `<PROJECT_ROOT>/00_OD工作区/01_方法论/` 的上位真源。

## 6. 推荐产物清单

OD 工作区建议至少形成以下项目级输入产物：

1. 项目方法论输入说明
2. To-Be 流程梳理结果
3. 项目组织分工说明
4. 项目权限矩阵初稿
5. 项目字典引用与补充清单
6. OD 阶段问题清单

若项目成熟度较高，还可继续补充：

1. 标准业务流程登记表
2. 产品经理开发引用组织清单
3. 产品经理开发引用权限清单
4. 字典正式词条卡和词条总表草稿

## 7. 推荐使用顺序

若在 OD 工作区中新增、改写或补写正式文档，建议按以下顺序执行：

1. 先看 `<TOOL_REPO_ROOT>/06_工作规范/02_OD工作规范/方法论-方法论工作体系方法论（道法术器_制度完整版V1）.md`
2. 再看 `<TOOL_REPO_ROOT>/06_工作规范/02_OD工作规范/附件-模型-流程分类与分层定义.md` 与 `<TOOL_REPO_ROOT>/06_工作规范/02_OD工作规范/附件-模型-字典顶层域与子域结构.md`
3. 再看 `<TOOL_REPO_ROOT>/07_公共模板库/01_OD工作模板/README.md`
4. 如涉及标准术语、角色、状态和枚举，再看 `<TOOL_REPO_ROOT>/04_标准词典库/`
5. 如需 AI 协作，再看 `<TOOL_REPO_ROOT>/08_AI工作站/01_AI能力模块/01_OD工作区能力模块/`
6. 形成 OD 输入后，由产品经理使用 `od-demand-analyzer` 解析并承接到 `<PROJECT_ROOT>/02_一号仓库/02_需求确认/`

## 8. 与一号仓库的关系

1. `<PROJECT_ROOT>/00_OD工作区/` 是一号仓库的重要上游输入源。
2. `<PROJECT_ROOT>/00_OD工作区/` 的内容与 `<PROJECT_ROOT>/02_一号仓库/01_需求调研/` 是并列输入，不是前后继承关系。
3. 二者共同进入 `<PROJECT_ROOT>/02_一号仓库/02_需求确认/`。
4. `<PROJECT_ROOT>/00_OD工作区/` 的内容不得跳过确认层直接进入 `<PROJECT_ROOT>/02_一号仓库/03_需求分析/`。
5. 后续正式用户故事、URD 等需求真源，仍然只在 `<PROJECT_ROOT>/02_一号仓库/03_需求分析/` 中形成。

## 9. 进入一号仓库确认层前的最小门禁

进入 `<PROJECT_ROOT>/02_一号仓库/02_需求确认/` 前，建议至少确认：

1. 当前项目的方法论输入口径已明确
2. To-Be 流程已有初稿或确认稿
3. 项目组织分工已明确主要角色
4. 核心权限边界已有初步共识
5. 核心业务术语和项目补充字典已登记

## 10. 与后续仓库的关系

1. `<PROJECT_ROOT>/00_OD工作区/` 的直接承接目标是 `<PROJECT_ROOT>/02_一号仓库/02_需求确认/`。
2. 其内容可影响零号仓库和后续仓库的范围边界，但不直接替代这些仓库的正式产物。
3. 若项目后续初始化需要引用 OD 输入，应优先通过一号仓库已确认结果进行承接。

## 11. 禁止事项

1. 不得把标准词典真源直接改写到本目录
2. 不得把 DIC 规范正文复制到本目录
3. 不得将一号到四号仓库的正式产物提前落在本目录
4. 不得把 OD 输入直接当作 `<PROJECT_ROOT>/02_一号仓库/03_需求分析/` 的正式需求真源

## 12. 一句话说明

**OD 工作区负责承接并沉淀 OD 输出的业务原始需求输入，供一号仓库确认层正式承接。**
